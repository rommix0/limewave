# Limewave v0.5 (SFZ instruments) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Open, edit, audition and save SFZ instruments: a region list, a key-by-velocity map, per-region settings, and `.sfz` saving with its WAVs.

**Architecture:**
- `limewave-core` gains an `sfz` module with no UI or audio code. It covers:
  - the parser, a flat token stream that keeps everything;
  - the instrument model with inheritance and region-level edits;
  - the writer;
  - sample-path resolution;
  - sample binding (instrument values into each WAV's `EditState`, and changes back out);
  - Auto-map and Fill gaps;
  - instrument saving.
- The app holds one optional instrument whose samples are the ordinary `files` sessions.
- The audio engine gains a lock-free swapped instrument map of per-region play buffers that share audio by `Arc`, plus note velocity.

**Tech Stack:** Rust 2024 (1.85), eframe/egui 0.37, cpal 0.18, midir 0.11, arc-swap 1.9, rtrb 0.4, rfd 0.17, egui_kittest 0.37, tempfile. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-10-22-limewave-sfz-design.md`. It builds on the v0.1 to v0.4 specs in the same folder.

## Global Constraints

- Never name third-party programs or audio products in code, comments, UI text, docs or commit messages.
- Permissive dependencies only, and `cargo deny check licenses` must stay clean. This plan adds no crates.
- Files in `samples/` are never committed (the folder is git-ignored). Automated tests generate their own WAVs and `.sfz` text. The one exception is an `#[ignore]`-free test that **skips itself** when `samples/RSB 501-01` is absent (Task 7).
- The audio thread never allocates, locks, blocks or frees. Swapped-out shared data is retired on the UI thread, following the existing `AudioEngine::set_buffer` / `retired` pattern.
- Every task ends with these all passing:
  - `cargo fmt --check`
  - `cargo clippy --workspace --all-targets -- -D warnings`
  - `cargo test --workspace`
- Fine tune = −`tune` (spec §4.2).
- Middle C = MIDI 60 = `C4` = SFZ `c4`.
- SFZ defaults:
  - `lokey` 0, `hikey` 127, `lovel` 1, `hivel` 127, `pitch_keycenter` 60, `tune` 0, `transpose` 0, `volume` 0, `amp_veltrack` 100, `offset` 0;
  - `ampeg_attack` 0, `ampeg_decay` 0, `ampeg_sustain` 100, `ampeg_release` 0.
- Default note velocity for the computer keyboard and on-screen keys is **100**.
- Version **0.5.0**.
- Commit messages are conventional (`feat(core): …`, `feat(app): …`, `test(…)`, `docs: …`). Never stage `session_memory.json`.

## Review Focus

1. **One WAV named two ways.** Two regions name the same file with different separators or case (`Samples\EP A1 mp.wav` and `samples/ep a1 mp.wav` on a case-insensitive match). They must bind to **one** sample, not load it twice. *Test in Task 2.*
2. **A saved copy must find its samples.** Saving an instrument whose samples sit in a subfolder, to a new folder, must reopen with every region's sample found. This includes `..` paths, which are moved into `samples/`. *Tests in Task 12.*
3. **No stuck notes.** A one-shot region ignores note-off, but Stop (`AllOff`) must still silence it. Layered notes beyond the voice count must steal voices, not leave held voices that never release. *Tests in Task 6.*
4. **The selection stays valid after a region change.** Deleting the selected region, or undoing an Add, must leave the selection valid and the editor showing a loaded sample or nothing. *Tests in Tasks 8 and 10.*
5. **Moving the Start marker of a sample whose regions have `offset`.** The offset is shifted and clamped at 0, never wrapped or made negative. Loop opcodes are clamped to the new length. *Test in Task 4.*

**Interfaces:**
- Produces:
```rust
pub enum HeaderKind { Control, Global, Master, Group, Region, Other(String) } // Other keeps the name without <>
pub enum Token {
    Header(HeaderKind),
    Opcode { name: String, value: String },      // value: raw text as written (may contain $NAME), trimmed
    Comment(String),                              // full text incl. `//` or `/* … */`
    Define { name: String, value: String },       // `#define $NAME value`; name includes the `$`
}
pub struct SfzFile { pub tokens: Vec<Token>, pub crlf: bool }
#[derive(Debug, thiserror::Error)] pub enum SfzError { #[error("This instrument uses #include, which Limewave can't open yet")] Include }
pub fn parse(text: &str) -> Result<SfzFile, SfzError>;
pub fn decode_text(bytes: &[u8]) -> String;      // UTF-8 (BOM stripped), else Latin-1 byte-per-char
pub fn expand(value: &str, defines: &[(String, String)]) -> String; // replaces $NAME occurrences, longest name first
```
- A header owns every token after it until the next header. Tokens before the first header belong to no header.

  - `comments_are_kept_in_place`: both `// x` and `/* a\nb */` come back as `Comment` tokens at their positions. A `//` after a value ends the value.
  - `defines_are_kept_and_expandable`: `#define $KEY 60` gives `Define{"$KEY","60"}`. `expand("$KEY", ..)` gives `"60"`, and `$KEY2` with a longer define wins over `$KEY`.

pub enum Keycenter { Note(u8), Sample }
pub enum SfzLoopMode { NoLoop, OneShot, Continuous, Sustain }
pub enum LoopDir { Forward, Backward, Alternate }
pub struct Ampeg { pub attack: f32, pub decay: f32, pub sustain: f32 /*%*/, pub release: f32 } // seconds
pub struct RegionInfo {
    pub sample: Option<String>, pub lokey: u8, pub hikey: u8, pub lovel: u8, pub hivel: u8,
    pub keycenter: Keycenter, pub tune: f32, pub transpose: i32, pub volume: f32, pub amp_veltrack: f32,

}
impl Instrument {
    pub fn new(file: SfzFile) -> Instrument;
    pub fn regions(&self) -> Vec<usize>;                 // token index of each <region> header, in order ("region n" = regions()[n])
    pub fn groups(&self) -> Vec<usize>;                  // token index of each <group> header
    pub fn group_of(&self, region: usize) -> Option<usize>;   // region n -> group number (index into groups()), None before the first <group>
    pub fn get(&self, region: usize, name: &str) -> Option<(String, Level)>; // effective, expanded, alias-aware
    pub fn region_info(&self, region: usize) -> RegionInfo;
    pub fn set(&mut self, region: usize, name: &str, value: &str);          // region-level, in place or appended
    pub fn add_group(&mut self) -> usize;                                  // appends "<group>", returns group number
    pub fn add_region(&mut self, group: Option<usize>, sample: &str, key: u8) -> usize; // at end of group; opcodes sample, pitch_keycenter, lokey, hikey; returns region n

    pub fn move_region(&mut self, region: usize, group: usize) -> usize; // to end of group, returns new region n
    pub fn other_settings(&self, region: usize) -> Vec<(String, String, Level)>; // effective opcodes not in the §3.4 table
    pub fn default_path(&self) -> String;                // <control> default_path, expanded, "" if none
}
// paths.rs
pub fn sample_path(sfz_dir: &Path, default_path: &str, sample: &str) -> PathBuf; // '\\' and '/' both separators; absolute kept
pub fn find_sample(path: &Path) -> Option<PathBuf>;     // exact file, else a case-insensitive match of each component; None if missing or name starts with '*'

pub struct SampleBinding { pub path: PathBuf /*found file*/, pub regions: Vec<usize>, pub follows: Vec<bool> /*parallel to regions; regions[0] always true*/ }
pub struct Binding { pub samples: Vec<SampleBinding>, pub region_sample: Vec<Option<usize>> /*region n -> samples index; None = missing*/ }

- `write_back` (spec §7.2) does two things:
  - (a) If `root`, `cents`, `loop_mode`, `loop_start` or `loop_end` differ between `before` and `after`, it sets the following explicit opcodes on every region where `follows` is true:
    - `pitch_keycenter` = root;
    - `tune` = `format_number(-cents)`;
    - `loop_mode`:
      - `no_loop` when `LoopMode::Off`, unless the region's `loop_mode` is `one_shot`, which is kept;
      - otherwise the region's existing `loop_sustain` is kept, else `loop_continuous`;
    - `loop_start` and `loop_end`, shifted by `-after.start` (only when looped);
    - `loop_type` only when not forward (`backward` or `alternate`).
  - (b) If `after.start != before.start` or `after.end != before.end`, then on every region of the sample (following or not) it shifts the existing `offset`, `end`, `loop_start` and `loop_end` by `-(after.start - before.start)`. The results are clamped to `0..=after.end - after.start`.

### Task 5: Saving an instrument (core)

**Files:**
- Create: `crates/limewave-core/src/sfz/save.rs`
- Modify: `crates/limewave-core/src/save.rs`. Make `write_atomic`, `backup_existing` and `make_backup` `pub(crate)` for reuse; their behaviour is unchanged.

**Interfaces:**
- Consumes:
  - Tasks 2 to 4;
  - `save::{build_wav_bytes, Destination, SaveOutcome}` and `SaveError`.
- Produces:
```rust
pub struct SampleSave<'a> { pub doc: &'a WavDocument, pub initial: &'a EditState /*history.first()*/, pub edit: &'a EditState }
pub struct InstrumentSaved { pub sfz: PathBuf, pub written: Vec<SaveOutcome> /*sfz first, then each WAV written or copied*/ }
pub fn save_instrument(inst: &Instrument, sfz_path: &Path /*where it was read from, or the picked path when untitled*/,
    binding: &Binding, samples: &[Option<SampleSave>] /*parallel to binding.samples*/,
    dest: &Destination, write_smpl: bool) -> Result<InstrumentSaved, SaveError>;
pub fn wav_edit_for_save(doc: &WavDocument, edit: &EditState, write_smpl: bool) -> EditState; // write_smpl=false: root, cents, loop_mode, loop_start, loop_end from doc.initial_edit()
pub fn needs_rewrite(doc: &WavDocument, e: &EditState) -> bool;   // e != doc.initial_edit()
```
- Steps inside `save_instrument`:
  1. Clone the instrument. For each loaded sample, call `write_back(clone, sample, initial, edit)`.
  2. Find the target `.sfz` path:
     - `Folder(d)`: `d/<file name>`;
     - `OverwriteWithBackup` and `ReplaceSaved`: `sfz_path`;
     - `File(p)`: `p`.
  3. Map each sample to its target:
     - its path relative to the source `.sfz` folder, kept under the target folder;
     - if it is outside the source folder, `<target dir>/samples/<file name>`, with `sample=` rewritten using `/` on every region of that sample.
  4. Write each WAV:
     - when `needs_rewrite`, write `build_wav_bytes(doc, &wav_edit_for_save(..))`;
     - otherwise, for `Folder` or `File`, copy the source bytes, and for `Overwrite` or `ReplaceSaved`, skip it.
     - `OverwriteWithBackup` backs up each replaced WAV.
     - `Folder` refuses a target equal to the source (`WouldOverwriteOriginal`), as WAV saving does.
  5. Write the `.sfz` last, atomically, with a backup for `OverwriteWithBackup`, and with `File` backing up an existing different file.

- Behaviour:
  - With an instrument set, `NoteOn` starts one voice per matching region:
    - the region matches when `lokey ≤ note ≤ hikey` and `lovel ≤ velocity ≤ hivel`;

    - `Normal` clears it, ignoring the session `release_past_loop`;

  - The UI side keeps swapped-out maps in a `retired` list until only that list holds them.
