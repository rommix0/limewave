# Limewave v0.7 Spectrogram View and Click Repair Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:**
- A **Waveform | Spectrogram** switch over the main view, with a musical (octave) frequency axis.
- **Effects ▸ Repair click**, which rebuilds a selection of up to 50 ms from the audio on either side, as one undoable, same-length step.

**Architecture:**
- **Core** gets two pure DSP modules:
  - `dsp/declick.rs`: Burg AR forward/backward extrapolation, blended across the gap.
  - `dsp/spectrogram.rs`: a short-time FFT resampled onto an octave axis, quantised to bytes.
- **Edit helper:** `edit.rs` wraps a repair as an `Op::Splice` of kind `Draw`, with its whole range marked generated, so it is tinted and moves nothing.
- **App:**
  - adds a `ViewMode`, remembered in eframe storage;
  - computes each file's spectrogram on a worker thread, cached per audio version;
  - draws it as texture tiles in place of the waveform lanes. Everything else in the view is drawn over it unchanged.

**Tech Stack:** Rust workspace (`limewave-core`, `limewave`), eframe/egui 0.37, egui_kittest, realfft. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-10-23-limewave-spectrogram-declick-design.md`

## Global Constraints

- No third-party program or product names anywhere: code, comments, UI text, docs or commit messages. Say "an old hardware sampler".
- Permissive licences only; `cargo deny check licenses` stays clean. No new dependencies.
- `MAX_REPAIR_MS = 50.0`, measured at the file's effective rate (`rate_after`).
- Spectrogram: lowest frequency C1 = `32.703_195_662_574_83` Hz, dB floor `-90.0` dBFS. The top of the axis is half the effective rate.
- The view choice is saved under the storage key `"view_mode"` with the values `"waveform"` and `"spectrogram"`.
- Every task ends with `cargo fmt --all`, `cargo clippy --workspace --all-targets -- -D warnings` and `cargo test --workspace` all clean. Commit only that task's files, and never `session_memory.json`.
- Comment density and naming match the surrounding code: doc comments on every pub item, British spelling in UI text and docs.
- Version: `0.7.0`.

## Review Focus

1. **Repair at the limits.**
   - A selection of exactly 50 ms is accepted, and one frame more is refused.
   - On a converted file (31,250 Hz), the limit is counted at that rate, not the file header's.
   - Tested in Task 2.
2. **Odd selections.**
   - A selection dragged right to left (`a > b`) is accepted.
   - A one-frame click is accepted.
   - A selection that starts inside a generated tail is accepted too: the tint ranges merge.
   - Tested in Tasks 2 and 3.
3. **Tiny or silent files in the spectrogram.**
   - A file shorter than one FFT window, or a new silent sample, gives an all-black picture with no panic.
   - Tested in Task 4.
4. **Very long files.**
   - A 10-minute file never gets more than `MAX_COLUMNS` columns.
   - The window keeps drawing frames while the spectrogram computes.
   - Tested in Tasks 4 and 6; speed is a checklist row.
5. **Stale spectrogram results.**
   - Undo, or switching files, while a spectrogram is computing must not show a picture made for other audio.
   - Tested in Task 6.

### Task 1: Click rebuilding (DSP)

**Files:**
- Create: `crates/limewave-core/src/dsp/declick.rs`
- Modify: `crates/limewave-core/src/dsp/mod.rs` (add `pub mod declick;` and mention it in the module doc)

**Interfaces:**
- Produces:
  - `pub fn order_for(gap: usize) -> usize`: `(gap / 8).clamp(32, 256)`.
  - `pub fn context_needed(gap: usize) -> usize`: `gap.max(3 * order_for(gap))`. This is the real audio needed on each side.
  - `pub fn rebuild(channel: &[f32], first: usize, last: usize) -> Option<Vec<f32>>`:
    - returns the `last - first + 1` new values for `channel[first..=last]`;
    - returns `None` when `first > last`, `last >= channel.len()`, or either side has fewer than `context_needed` frames. The left side is `first` frames and the right side `channel.len() - 1 - last` frames.

- [ ] **Step 1: Write the failing tests** in the module's test module. Use `testwav::sine` and a local `db(err_rms / ref_rms)` helper.
  - `a_spike_in_a_sine_is_rebuilt`:
    - a 440 Hz sine at 44,100 Hz, amplitude 0.5, 8,000 frames, with `x[4000] = 1.0`;
    - `rebuild(&x, 4000, 4000)`;
    - the error against the clean sine at 4000 is below −40 dB of 0.5.
  - `a_noise_burst_in_a_sine_is_rebuilt`:
    - 88 frames (2 ms) from 4000 overwritten with `rng`-seeded noise of amplitude 0.8;
    - the RMS error over the range is below −40 dB of the sine's RMS.
  - `a_fifty_ms_gap_comes_back_at_full_level`:
    - a 220 Hz sine at 44,100 Hz, amplitude 0.5, 20,000 frames, zeroed over 2,205 frames from 8,000;
    - the rebuilt range's RMS is within 1 dB of the sine's;
    - `|y[0] − clean[8000]|` and `|y[last] − clean[10204]|` are both below 0.025, so there is no step at the edges.
  - `too_little_context_is_refused`:
    - `rebuild(&x, 10, 10)` is `None` when `context_needed(1) = 96`;
    - the same holds at the right edge;
    - an empty range gives `None`, and so does `last >= len`.
  - `rebuilding_is_deterministic`: two calls give equal output.

- [ ] **Step 2: Run** `cargo test -p limewave-core --lib dsp::declick`. Expected: FAIL to compile.

- [ ] **Step 3: Implement.** The algorithm, in f64 throughout:
  - `m = last - first + 1`, `p = order_for(m)`, and the context length on each side is `n = min(available, max(4 * m, 8 * p))`.
  - **Burg's method** fits AR coefficients `a[1..=p]` so that `x[t] ≈ −Σ a[k]·x[t−k]`:
    - keep forward and backward error arrays;
    - each stage's reflection coefficient is `k = −2·Σ f[t]·b[t−1] / Σ (f[t]² + b[t−1]²)`, or 0 when the denominator is 0;
    - Levinson-update `a` with it.
  - **Forward:** fit on the left context `channel[first−n..first]` and run the predictor `m` steps past `first − 1`.
  - **Backward:** fit on the right context reversed, `channel[last+1..last+1+n]` reversed, then predict `m` steps the same way and reverse the result.
  - **Blend:** `y[t] = w[t]·fwd[t] + (1 − w[t])·bwd[t]`, where `w[t] = 0.5 + 0.5·cos(π·(t + 1)/(m + 1))`.
  - Return the values as f32. If the tests need it, a least-squares AR interpolation may replace the blend; keep the signatures.

- [ ] **Step 4: Run** `cargo test -p limewave-core --lib dsp::declick`. Expected: PASS. Don't loosen the tests; raise the order cap or context first.

### Task 4: Spectrogram analysis (DSP)

**Files:**
- Create: `crates/limewave-core/src/dsp/spectrogram.rs`
- Modify: `crates/limewave-core/src/dsp/mod.rs`

**Interfaces:**
- Consumes: `spectrum::{Fft, hann}` (existing).
- Produces:
  - Constants:
    - `pub const LOWEST_HZ: f64 = 32.703_195_662_574_83;`
    - `pub const FLOOR_DB: f32 = -90.0;`
    - `pub const ROWS: usize = 512;`
    - `pub const MAX_COLUMNS: usize = 16_384;`
  - `pub struct Spectrogram { pub columns: usize, pub hop: usize, pub rate: u32, pub frames: usize, pub channels: Vec<Vec<u8>> }`:
    - one `Vec` per channel, row-major (`row * columns + column`), with row 0 at the top (the Nyquist frequency);
    - each value is 0 at `FLOOR_DB` or below and 255 at 0 dBFS or above, linear in dB between.
  - `pub fn hop_for(frames: usize) -> usize`: `frames.div_ceil(MAX_COLUMNS).max(64)`.
  - `pub fn fft_size_for(rate: u32) -> usize`: the largest power of two ≤ `rate / 20`, clamped to `256..=16_384`.
  - `pub fn row_hz(row: usize, rate: u32) -> f64`: `LOWEST_HZ · (nyq / LOWEST_HZ)^(1 − (row + 0.5) / ROWS)`, where `nyq = rate / 2`.
  - `pub fn hz_y_fraction(hz: f64, rate: u32) -> f32`: `1 − ln(hz / LOWEST_HZ) / ln(nyq / LOWEST_HZ)`, clamped to `0..=1`. 0 is the top and 1 the bottom.
  - `pub fn spectrogram(audio: &[Vec<f32>], rate: u32) -> Spectrogram`. Column `c` covers frames `c·hop .. (c+1)·hop`, and `columns = frames.div_ceil(hop)`.
  - **Algorithm:**
    - the Hann window of `fft_size_for(rate)` is centred on `c·hop + hop/2`, with zero padding outside the file;
    - a bin's dBFS is `20·log10(|X| · 4 / n)`, so a full-scale sine reads 0 dB;
    - each row takes the largest bin magnitude between its neighbours' centre frequencies, or a linear interpolation of the two nearest bins when that band is narrower than one bin.

- [ ] **Step 1: Write the failing tests:**
  - `a_440_hz_sine_is_brightest_on_a4`: 1 s at 44,100 Hz, amplitude 0.5. In the middle column, the brightest row's `row_hz` is within a semitone of 440.
  - `the_axis_runs_from_c1_to_the_nyquist`:
    - `row_hz(0, 22_050)` is within one row step of 11,025;
    - `row_hz(ROWS − 1, 22_050)` is within one row step of `LOWEST_HZ`;
    - `hz_y_fraction(LOWEST_HZ, r) == 1.0` and `hz_y_fraction(r / 2, r) == 0.0`.
  - `silence_is_floor_and_a_full_scale_sine_is_bright`:
    - zeros give all 0s;
    - a full-scale 1 kHz sine's peak value is at least 240.
  - `columns_follow_the_hop`:
    - 44,100 frames give hop 64 and `columns == 690`;
    - 26,460,000 frames (10 min) give `columns <= MAX_COLUMNS`.
  - `tiny_files_do_not_panic`: 10 frames and 0 frames, with no panic; 0 frames gives 0 columns.
  - `stereo_channels_are_analysed_separately`: silence on the left and a sine on the right; the left is all 0.

### Task 6: Drawing the spectrogram

**Interfaces:**
- Consumes: `spectrogram`, `hz_y_fraction`, `Spectrogram` (Task 4); `ViewMode` (Task 5); `spawn_render` and `RenderJob` (existing); `colors::LIME`.
- Produces, in `ui/spectrogram.rs`:
  - `#[derive(Default)] pub struct SpectrogramCache`. It holds the running job for an `audio_version`, and the picture shown: its version, its `frames`, `hop`, `columns`, and per channel a `Vec` of `TextureHandle` tiles, each up to 2,048 columns wide and `ROWS` tall, with linear filtering.
  - `pub struct Picture { pub version: u64, pub frames: usize, pub hop: usize, pub columns: usize, tiles: Vec<Vec<TextureHandle>> }`: the shown picture, with one `Vec` of tiles per channel.
  - `pub fn update(cache: &mut SpectrogramCache, ctx: &egui::Context, processed: &[Vec<f32>], rate: u32, version: u64)`:
    - if no job or picture exists for `version`, start `spawn_render` of `spectrogram` on a copy of `processed`;
    - when a job finishes and its version is still current, build the tiles and make it the picture;
    - a finished job for an older version is dropped.
  - `pub fn block_until_ready(cache: &mut SpectrogramCache, ctx: &egui::Context)`, for tests: it waits for the running job and takes its result as `update` would.
  - `pub fn picture_for(cache: &SpectrogramCache, frames: usize) -> Option<&Picture>`:
    - returns the shown picture when its `frames` equals `frames`, even if it is from an older version, so the old picture stays up after a same-length edit;
    - otherwise returns `None`, and the waveform is drawn.
  - `pub fn draw_lanes(painter: &egui::Painter, rect: Rect, view: &ViewTransform, picture: &Picture, channels: usize, rate: u32)`. For each lane (`lane_rect`):
    - it paints the tiles that overlap the visible frames, at `view.frame_to_x(tile_first_frame)..frame_to_x(tile_end_frame)`;
    - it draws a faint hline and a small "C1"…"C9" label (from `notes::note_name`) at each C below the Nyquist, at `hz_y_fraction`, inside the lane's left edge.
  - `pub fn spectro_color(v: u8) -> Color32`: a lerp from the view `BACKGROUND` to `colors::LIME` at `t = (v / 255)^1.5`.
- In `waveform_view`, when `ui_state.view_mode == Spectrogram`:
  - call `update`;
  - in `draw`, use `draw_lanes` instead of the `draw_lane` loop when `picture_for` returns a picture;
  - leave everything after the lanes unchanged: tint, shades, loop, ruler, markers and cursors;
  - the input handling is unchanged.
