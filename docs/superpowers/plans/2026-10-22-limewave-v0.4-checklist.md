Status key: **verified (how)**, **covered by automated test (name)**, or **NOT verified: needs a human (what to do)**.

Run on Windows 10 (MSVC, Rust stable) on 2026-10-22. This release adds Draw mode, File → New… blank samples and recording from an input device. The rows below are the spec's §8.3 manual checks and the release checks for the new toolbar and window behaviour. None of them has been run by hand yet, so every row is **NOT verified** until the user has tried it.

## Spec section 8.3 checks: manual

| Check | Status |
| --- | --- |
| Record a short note from a real audio interface at **44.1 kHz**: the panel shows 44100 Hz, the take plays back at the right pitch and speed, and nothing clicks or drops. Steps: open **Record**, choose the interface, choose the input channels, press **Record**, play a note on the instrument, press **Stop**, then play the new "Recording 1" file. | NOT verified: needs a human, with a real audio interface or microphone and the app (`cargo run --release -p limewave`). |
| Record the same note at **48 kHz** (set the interface to 48 kHz first, then check the panel shows 48000 Hz). Same checks as above. | NOT verified: needs a human, with a real audio interface or microphone and the app. |
| **New…** with **One cycle of C4**, Draw on: draw a single cycle of the waveform, play it on the keyboard (Audition on), and check it holds a steady pitch. The cents readout should be close to 0. | NOT verified: needs a human, with the app and the computer keyboard or a MIDI keyboard. |
| Open a long file (several minutes), zoom all the way out, turn **Draw** on, and drag across a channel lane: the window stays responsive while the stroke is drawn, and the undo step on release does not stall. | NOT verified: needs a human, with the app and a long file of your own. |

## Release checks: the new toolbar and window behaviour

| Check | Status |
| --- | --- |
| **Escape turns Draw off** when nothing else uses it. With Draw on and no menu or text field open, press Escape: the Draw toggle goes off. With a menu open, Escape only closes the menu and Draw stays on. | NOT verified: needs a human, with the app. |
| **Draw toggle:** with Draw on, a drag on a channel lane draws and a click with no drag only sets the play-from point; a marker still drags. With Draw off, dragging a sample dot moves it as before. Each stroke is one undo step (Ctrl/Cmd+Z removes the whole stroke). | NOT verified: needs a human, with the app. |
| **Unsaved prompt with a take:** record a take, do not save it, then open another file or folder. The unsaved-changes prompt appears, because a take is an untitled file that counts as unsaved. Choosing Save all opens Save as… for the take, and cancelling that cancels the held action. | NOT verified: needs a human, with the app and an audio input device. |
| **Window title:** with a file selected, the title reads "<name> – Limewave" (for example `Untitled 1.wav – Limewave`); with nothing selected it reads "Limewave"; after a save renames the file, the title follows the new name. | NOT verified: needs a human, with the app. |
| **Toolbar glyph:** the Draw toggle shows the pencil glyph followed by "Draw" (`✏ Draw`) in the toolbar, with no missing-character box in the app's font. If the glyph does not render, the toggle still works and the label should be changed to plain "Draw". | NOT verified: needs a human, with the app on Windows, macOS and Linux (the fonts differ). |

## Known limitations

These are known and deliberately left for a later version.

- The Record panel does not monitor the input; listen through the audio interface. A microphone may also pick up the program's own output; that is the user's business.
- A take stops at 10 minutes, or if audio is lost while the computer is busy. What was recorded is kept, and the panel says why it stopped.
- The Draw toggle is per window, not per file, and is not saved.
