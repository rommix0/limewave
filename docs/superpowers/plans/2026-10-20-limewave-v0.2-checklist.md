# Limewave v0.2: release checklist

Status key: **verified (how)**, **covered by automated test (name)**, or **NOT verified: needs a human (what to do)**.

Run on Windows 10 (MSVC, Rust stable) on 2026-10-21. No listening, visual, MIDI-hardware, macOS or Linux checks have been done by a human. Everything marked "NOT verified" below is still open. Test names without a path are in the integration test file for that area (`tests/effects.rs`, `tests/selection.rs`, `tests/inspector.rs`, `tests/waveform.rs`, `tests/audition.rs`, `tests/save.rs` in the `limewave` crate); the rest are unit tests named by module.

## Known limitations

These are known and deliberately left for a later version.

- Cue markers are kept and kept in step with trims and reverses, but Limewave does not show or edit them.
- The envelope is for audition only. It is not saved into WAV files.
- A backward loop has no crossfade (the control is disabled and any crossfade value is kept for when the mode changes back).
- Many samplers ignore backward loops.
- Only one release tail survives rapid file switching: when files are switched quickly, the most recent release tail keeps sounding and earlier ones are cut. A switch through a file that is still loading does not count as a switch.
- The v0.1 limitations that this release did not address are unchanged (see the v0.1 checklist): the engine gets a full copy of the audio on each edit, a fine tune of exactly -50 cents reopens as +50 cents on the note below, and files over 4 GiB are refused.
