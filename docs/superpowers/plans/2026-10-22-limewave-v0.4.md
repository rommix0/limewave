# Limewave v0.4 (drawing, new samples, recording) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build three features:
- a Draw mode that draws the waveform at any zoom;
- File → New… blank samples;
- recording from an input device into new untitled files.

**Architecture:**
- **Core (`limewave-core`)** gets note-frequency helpers and `new_document`. It builds an in-memory `WavDocument` by writing real WAV bytes (`fmt `, `fact` for float, `smpl`, `data`) and loading them with `load_wav_bytes`. Because the document already carries `smpl` and `fact`, the existing save path keeps them with no new branch.
- **The app** marks such sessions `untitled`:
  - they count as unsaved from creation;
  - they are saved one at a time through an injectable save-file picker and a new `Destination::File`.
- **Drawing** reuses the v0.3.x pencil (`PencilStroke`, `redraw_samples`).
- **Recording** splits into three parts:
  - an engine-free capture core (`audio/record.rs`): an rtrb ring fed by the audio callback, and a capture thread that drains it into the take;
  - a cpal input layer;
  - a modal Record panel.

**Tech Stack:** Rust 2024, eframe/egui 0.37, cpal 0.18, rtrb 0.4, rfd 0.17, egui_kittest 0.37.

**Spec:** `docs/superpowers/specs/2026-10-22-limewave-drawing-and-recording-design.md`. It builds on the v0.1–v0.3 specs in the same folder.

**Branch:** work on `limewave-v0.4`, cut from master (master is at 2244105 or later).

## Global Constraints

- Never name third-party programs or audio products in code, comments, UI text, docs or commit messages.
- Permissive licences only; `cargo deny check licenses` stays clean. No new dependencies are needed: `rtrb`, `cpal`, `rfd` and `arc-swap` are already in `crates/limewave/Cargo.toml`.
- Never stage `session_memory.json`.
- Every task ends green:
  - `cargo fmt --all`;
  - `cargo clippy --workspace --all-targets -- -D warnings`;
  - `cargo test --workspace`.
- UI copy is fixed by the spec. Use its exact strings:
  - "Draw the waveform with the mouse (each stroke is one undo step)"
  - "No audio input device found"
  - "Recording stopped at the 10-minute limit"
  - "Recording stopped: audio was lost while the program was busy"
  - "Stop and keep the take?"
  - "Untitled files are saved one at a time with Save as…"
- The 10-minute cap is `600 * rate` frames, for both New… and recording.
- The default root note is MIDI 60, shown as `C4`.
- The default bit depth is 16-bit everywhere.
- Names are "Untitled N" and "Recording N", counting from 1 for the whole run of the program.
- A file with no untitled sessions must behave and save exactly as in v0.3.

## Review Focus

1. **An unsaved new file or take is dropped without the prompt.** Closing, opening a file or folder, or Save all where the user cancels the picker must all keep the take. Tests: Task 3.
2. **The window is minimized or stalls during a take.** The capture thread must keep draining with no UI frames. Test: Task 6, `capture_thread_drains_without_the_ui`.
3. **A Draw stroke dragged off the lane, past the waveform's edges, or back over itself.** Values stop at full scale, frames stop at the file's ends, and redrawn frames take the newest values. Tests: Task 4.
4. **A 32-bit float new file.** It must save with a `fact` chunk and reload as float with the same length. Test: Task 2.
5. **A device running at 48 kHz.** The take's rate is the device rate, never resampled, and the saved file reports 48000. Tests: Task 6 and Task 8.

### Task 6: Capture core (engine-free)

**Files:**
- Create: `crates/limewave/src/audio/record.rs`
- Modify: `crates/limewave/src/audio/mod.rs`

**Interfaces:**
- Produces:
  - **`pub enum InputChoice { Mono(usize), Pair(usize) }`:**
    - an input index, or the first index of an adjacent pair;
    - `fn channels(self) -> usize`;
    - `fn label(self) -> String`: `"Mono"` on a 1-channel device, `"Input N"` (1-based), or `"Inputs N+M"`;
    - `pub fn input_choices(device_channels: usize) -> Vec<InputChoice>`: one channel gives `[Mono(0)]`; otherwise every `Mono(i)`, then `Pair(0)`, `Pair(2)`, and so on while `i + 1 < device_channels`;
    - `pub fn default_choice(device_channels: usize) -> InputChoice`: `Pair(0)` when there are 2 or more channels, else `Mono(0)`.
  - **`pub struct Feed`**, the audio-callback side, which only copies.
    - `pub fn push(&mut self, interleaved: &[f32])` takes device-interleaved frames of `device_channels`. It:
      - updates the meter peaks and the clip lights (at or above `10^(-0.1/20)`) for the chosen channels, always;
      - while recording, pushes the chosen channels, interleaved, into an `rtrb::Producer<f32>`;
      - if the ring lacks room for a whole block, sets the overflow flag and pushes nothing.
    - It never allocates or locks.
  - **`pub fn feed_error(&self, message: String)`**, for the stream's error callback. It sets a shared error the capture thread acts on.
  - **`pub struct Recorder`**, the app side.
    - `pub fn new(rate: u32, device_channels: usize, choice: InputChoice) -> (Recorder, Feed)`.
      - The ring holds at least `2 * rate * choice.channels()` samples.
      - It spawns the capture thread. Every ~5 ms the thread drains the ring into the take while recording, and stops the take on the cap (`600 * rate` frames, cut to exactly that), on overflow, or on a device error.
      - The thread exits when the `Recorder` drops.
    - `pub fn start(&mut self)` clears the take and the clip lights, then sets recording.
    - `pub fn stop(&mut self) -> Option<Take>` stops, drains what is left, and returns the take, or `None` for zero frames.
    - `pub fn poll(&mut self) -> Option<Take>` returns a take the thread stopped by itself (cap, overflow or error), once.
    - `pub fn recording(&self) -> bool` and `pub fn recorded_frames(&self) -> usize`.
    - `pub fn meter(&self) -> Vec<(f32 /*peak, linear*/, bool /*clip*/)>` and `pub fn clear_clip(&self, channel: usize)`.
  - **`pub struct Take { pub audio: Vec<Vec<f32>>, pub rate: u32, pub stopped: StopReason }`**
  - **`pub enum StopReason { User, Cap, Overflow, Device(String) }`.** `fn message(&self) -> Option<&'static str>` returns the two fixed messages for `Cap` and `Overflow`. `Device` is shown with its own text.
