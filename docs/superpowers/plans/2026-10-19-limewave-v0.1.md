# Limewave v0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Limewave v0.1, a cross-platform desktop app for hand-editing WAV loop points, root key and fine tune with a seam view and live audition, saving WAVs with `smpl` + `ISFT` metadata.

**Architecture:** A Cargo workspace with two crates. `limewave-core` is a pure library: RIFF/WAV I/O, edit state with undo, DSP (peaks, zero crossings, crossfade, seam data) and the save pipeline. It has no UI or audio-device code and holds almost all the tests. `limewave` is the eframe/egui app: an audio engine on `cpal` with a lock-free buffer swap, QWERTY and MIDI note input, and the views (waveform, overview, seam, inspector, file list, keyboard, save dialog). The UI keeps its maths in pure, tested helpers and draws with egui painters.

**Tech Stack:** Rust 1.98 (edition 2024), eframe/egui 0.37, cpal 0.18, midir 0.11, rfd 0.17, arc-swap 1.9, rtrb 0.4, thiserror 2, tempfile 3, egui_kittest 0.37 (dev), cargo-deny 0.20 (CI).

**Spec:** `docs/superpowers/specs/2026-10-19-limewave-design.md` (read it before starting any task; section numbers below refer to it).

## Global Constraints

- Licence: dual `MIT OR Apache-2.0`; `license = "MIT OR Apache-2.0"` in every `Cargo.toml`.
- Dependencies must be permissively licensed (MIT, Apache-2.0, BSD, ISC, Zlib or similar). No GPL/AGPL/LGPL crates. Font licences bundled by egui (OFL-1.1, Ubuntu Font Licence) are acceptable.
- Never name other commercial audio products in code, comments, UI text, docs or commit messages.
- Platforms: Windows, macOS, Linux. No platform-specific code beyond what crates handle.
- Software tag written into WAVs: `Limewave <version>`, from `env!("CARGO_PKG_VERSION")` of `limewave-core` (e.g. `Limewave 0.1.0`).
- Note naming: MIDI 60 = `C4`.
- `smpl` loop end is **inclusive**. A loop of `L` frames from `s` is stored as start `s`, end `s + L - 1`.
- The audio callback never allocates, locks or blocks.
- `samples/` is git-ignored and never committed; tests generate their own WAVs.
- Colours: panel `#1b1e25`, waveform `#5fb3ff`, loop region/markers `#ffc400`, start `#4ade80`, end `#f87171`, crossfade `#c084fc`, neon `#22d3ee`, lime `#a3e635`.
- Library code never panics on bad input files. Errors are values (`thiserror` enums), and lenient fixes are reported as warnings.

## Review Focus

The inputs and failure modes the spec implies but doesn't spell out, most likely to bite a user first. Each one has a pinned test in the task that owns the code.

1. **A file whose `smpl` loop is out of range** (end ≥ frame count, start > end), as written by careless tools. It should open with the loop clamped or disabled plus a warning, not panic. *Task 6, `initial_edit_clamps_out_of_range_loop`.*
2. **Zero-frame and one-frame files.** Opening, peaks, zero-crossing search, seam data and audition should all work without panicking. *Tasks 6, 7, 8, 10.*
3. **A crossfade longer than the audio allows**, including after the user shrinks the loop under an existing crossfade. The crossfade should clamp silently, never index out of bounds. *Task 5, `move_marker_reclamps_crossfade`; Task 8, `crossfade_clamped_to_available_audio`.*
4. **A save to a destination that doesn't exist or can't be written.** The folder should be created if missing. On failure the original stays untouched and no half-written target is left behind. *Task 9, `save_creates_destination_folder` and `failed_save_leaves_original_intact`.*
5. **A file sample rate different from the output device rate** (44.1 kHz file on a 48 kHz device). Audition pitch must stay correct. *Task 10, `step_accounts_for_rate_mismatch`.*

**Interfaces:**
- Consumes: `Chunk`, `list_type`, `find` (Task 1)

  - `pub fn info_set(chunks: &mut Vec<Chunk>, key: &[u8; 4], value: &str)`. This replaces the value inside the first `LIST/INFO` and keeps other sub-chunks and their order. With no INFO list, it appends a new `LIST/INFO` holding only this key. Values are NUL-terminated and padded to an even length.
  - `pub fn sync_inst(data: &mut [u8], root: u8, cents: f32)`. This sets byte 0 (unshifted note) to `root` and byte 1 (fine tune, `i8` cents) to `-(cents.round())` clamped to `-50..=50`. The `inst` field is the correction to *apply* on playback, while our `cents` is the sample's recorded pitch offset, hence the sign flip. Other bytes are untouched; it is a no-op if `data.len() < 7`.
  - `pub fn sync_acid(data: &mut [u8], root: u8)`. This sets the u16 root-note field at byte offset 4 to `root`; it is a no-op if `data.len() < 6`.
  - `pub fn note_name(n: u8) -> String` gives `C4` for 60, `C#4` for 61 and `C-1` for 0.
  - `pub fn parse_note(s: &str) -> Option<u8>` accepts `C4`, `c#4`, `Db4` and `60`.

### Task 5: Edit state, marker moves and undo history

**Files:**
- Create: `crates/limewave-core/src/edit.rs`

**Interfaces:**
- Produces:
  - `pub enum LoopMode { Off, Forward, PingPong }`, `pub enum FadeShape { EqualPower, Linear }` (both `Copy + PartialEq + Debug`)
  - `pub struct EditState { pub start: usize, pub end: usize, pub loop_mode: LoopMode, pub loop_start: usize, pub loop_end: usize, pub crossfade: usize, pub fade_shape: FadeShape, pub root: u8, pub cents: f32 }` (`Clone + PartialEq + Debug`). `start`, `end` and the loop points are inclusive frame indices.
  - `impl EditState { pub fn default_for(frames: usize) -> EditState; pub fn clamped(self, frames: usize) -> EditState; pub fn max_crossfade(&self) -> usize; pub fn loop_len(&self) -> usize }`
  - `pub enum Marker { Start, LoopStart, LoopEnd, End }`
  - `pub fn move_marker(e: &EditState, m: Marker, to: usize, lock_length: bool, frames: usize) -> EditState`
  - `pub struct History`, with `new(initial: EditState)`, `current(&self) -> &EditState`, `push(&mut self, s: EditState)` (dropping redo; a no-op if equal to current), `undo(&mut self) -> bool`, `redo(&mut self) -> bool`, `mark_saved(&mut self)`, `is_dirty(&self) -> bool`

Rules (pinned by the tests): `default_for(n)` gives start 0, end `n-1` (0 when `n == 0`), loop off, loop_start 0, loop_end `end`, crossfade 0, equal-power, root 60, cents 0. `clamped` keeps `start <= end < frames`. When the loop is on it also keeps `start <= loop_start <= loop_end <= end` with `loop_len >= 2`, and `crossfade <= max_crossfade()`. `max_crossfade() = min(loop_len, loop_start)`, because the fade reads `loop_start - N` (spec §6.6). `cents` is clamped to `[-50, 50]`.

  - `move_loop_end_stops_at_end_marker`: frames 1000, end 800, loop on; moving `LoopEnd` to 950 gives `loop_end == 800`.
  - `move_start_stops_at_loop_start`: moving `Start` past `loop_start` stops at `loop_start`.
  - `lock_length_moves_both`: loop 100..=199 with lock on; moving `LoopStart` to 150 gives 150..=249.
  - `lock_length_stops_at_bounds`: with lock on, moving to where `loop_end` would pass `end` stops so `loop_end == end` and the length is unchanged.
  - `move_marker_reclamps_crossfade`: crossfade 80 on loop 100..=299; moving `LoopEnd` to 149 gives `crossfade == 50`.
  - `max_crossfade_limited_by_loop_start`: loop_start 10, loop_len 500 gives `max_crossfade() == 10`.
  - `history_undo_redo_and_dirty`: push A then B; undo gives A and `is_dirty`; `mark_saved` on B makes it not dirty; pushing C then undoing back to B makes it not dirty.
  - `history_push_equal_is_noop`: pushing the current state again adds no undo step.

### Task 7: DSP: peak pyramid and zero crossings

**Files:**
- Create: `crates/limewave-core/src/dsp/mod.rs`, `dsp/peaks.rs`, `dsp/zerocross.rs`

**Interfaces:**
- Produces:
  - `pub struct PeakPyramid` with `pub fn build(channel: &[f32]) -> PeakPyramid` and `pub fn min_max(&self, channel: &[f32], from: usize, to_exclusive: usize) -> (f32, f32)`. It returns `(0.0, 0.0)` for an empty range and clamps the range to the channel length. Level 0 uses blocks of 64 samples, and each next level halves the count. Range queries combine whole blocks from the coarsest level that fits and scan the raw samples at the ragged ends.

**Files:**

**Interfaces:**
- Consumes: Tasks 1–8
- Produces:

  - `pub fn default_folder(source: &Path) -> PathBuf` = `<source dir>/limewave`

`build_wav_bytes` does the following, in order (spec §6.5–6.6):
1. Start from the original `data` bytes. If `crossfade_region` is `Some`, encode those frames with `encode_frames` and overwrite exactly their bytes. Bytes outside the region are never re-encoded.
2. Slice the frames `e.start..=e.end`.
3. Copy the chunk list in order, and:
   - drop `cue ` and `LIST/adtl`;
   - replace `data`;
   - for `smpl`, see step 4;
   - in `inst` / `acid`, call `sync_inst` / `sync_acid` if present;
   - `info_set(ISFT, software_tag())`;
   - keep every other chunk byte-for-byte.
4. `smpl`:
   - **Write one if** the doc had one, or if the root, cents or loop differ from `doc.initial_edit()`.
   - Take manufacturer, product, SMPTE fields, `sampler_data` and loops 1.. from the original, or zeros if there was none.
   - `sample_period(rate)`.
   - Unity and fraction from `tuning_to_smpl`.
   - Loop 0 is `{cue_id: 0, loop_type: 0 for Forward, 1 for PingPong, start: loop_start - e.start, end: loop_end - e.start, fraction: 0, play_count: 0}`. With the loop off there is no loop 0, but extra original loops are still kept if they fall inside the trimmed range; otherwise they are dropped with no error.
   - If there was no `smpl`, insert it right after `data`.

`save_wav` resolves the target: either `Folder(dir)/<file name>`, creating `dir` if missing, or the original path. For overwrite, it first `std::fs::copy`s the original to `backup_path` and returns `SaveError::Backup` without touching anything if that fails. It then writes the bytes to `tempfile::NamedTempFile::new_in(target_dir)` and `persist`s over the target.

The default `base` is 48. `pub fn octave_shift(key: egui::Key) -> Option<i8>`: Minus gives −12 and Equals gives +12.

Playback rules:
- The position is a fractional frame (`f64`).
- **Forward:** past `loop_end + 1`, subtract `loop_len`. Interpolation taps beyond `loop_end` read from `loop_start` onward.
- **Ping-pong:** reflect at both loop points.
- **Loop off:** play `start..=end` once, then the voice dies.
- On each call, if `pos > loop_end + 1` for the current `buf` (because the loop changed), wrap to `loop_start`.
- **Release:** a linear fade over `RELEASE_MS` at the device rate, then the voice dies.
