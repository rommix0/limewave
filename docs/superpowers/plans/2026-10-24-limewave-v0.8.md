# Limewave v0.8 Auto Loop Finder Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** a **Loop finder** panel beside the seam view. It searches the sound for loop points whose seam is hard to see and hear, lists up to 8 ranked candidates, previews one on click and applies it with **Use loop** as one undo step.

**Architecture:**
- **Core:** a new `loop_finder` module in `limewave-core`, as pure functions on `&[Vec<f32>]`:
  - `steady.rs`: the steady part and the search range;
  - `measure.rs`: the seam measures, the quality words and the score;
  - `search.rs`: the coarse band-level search, the sample-level refinement and the kept-point search;
  - `mod.rs`: the public types, `find_loops`, ranking and de-duplication;
  - `lab.rs`: the `loop_lab` bench.
- **App:**
  - `ui/loop_finder.rs` holds the global settings (remembered in eframe storage) and each session's search state: the running job, the result tied to `audio_version`, and the selected row. It also draws the panel and the waveform and overview brackets.
  - The search runs through `spawn_render`, with an `AtomicBool` to cancel it.
  - The preview reuses `Session::preview`.

**Tech Stack:** Rust workspace (`limewave-core`, `limewave`), eframe/egui 0.37, egui_kittest, realfft. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-10-24-limewave-loop-finder-design.md`

## Global Constraints

- No third-party program, product or hardware names anywhere: code, comments, UI text, docs or commit messages. Say "an old hardware sampler".
- Permissive licences only; `cargo deny check licenses` stays clean. No new dependencies.
- `MAX_SEARCH_SECONDS = 60.0`, at the effective rate (`Session::rate()`).
- `MAX_CANDIDATES = 8`.
- `DEFAULT_MIN_SECONDS = 0.1`, and no maximum by default.
- Preference 0.0 is tight, 1.0 is natural, and the default 0.5 is neutral.
- Quality words, best first: **Seamless**, **Good**, **Fair**, **Rough**.
- Loop points are inclusive frame indices in the processed audio's coordinates, as everywhere else.
- Settings are stored under the key `"loop_finder"`.
- Every task ends with `cargo fmt --all`, `cargo clippy --workspace --all-targets -- -D warnings` and `cargo test --workspace` all clean. Commit only that task's files, and never `session_memory.json` or anything in `samples/`.
- Doc comments on every pub item; comment density and naming match the surrounding code; British spelling in UI text and docs.
- Version: `0.8.0`.

## Review Focus

1. **Markers moved after a search.**
   - Results do not go stale when Start or End move, so a candidate can end up outside Start..End.
   - That row's **Use loop** must be disabled, with a hover note, rather than applying a clamped, different loop.
   - Tested in Task 7.
2. **The audio changes during a search or a preview.**
   - Undo, an effect or a file switch while searching or previewing must never apply or show a loop for other audio.
   - The preview ends, and the stale list greys out.
   - Tested in Tasks 6 and 7.
3. **Edges of the file.**
   - A selection starting at frame 0 must work.
   - A kept end in the last few frames must work too: 008's end is 10 frames before the end of the file, so there is almost no audio after the end. A short context is used, with no panic.
   - Tested in Task 3.
4. **Out-of-phase or one-sided stereo.**
   - Correlations sum per channel, so `R = −L` scores like mono.
   - A splice that is clean in L and broken in R is not *Seamless*.
   - Tested in Task 2.
5. **Tiny and huge inputs.**
   - A file shorter than a coarse frame, or a range shorter than the minimum, gives `RangeTooShort`, with no panic.
   - A 10-minute recording's steady part is cut to its last 60 s, while a 61 s selection is refused.
   - Tested in Tasks 1 and 3.

- Modify: `crates/limewave-core/src/lib.rs` (`pub mod loop_finder;`)

**Interfaces:**
- Produces, in `loop_finder`:
  - `pub const MAX_SEARCH_SECONDS: f64 = 60.0;`
  - `pub const MAX_CANDIDATES: usize = 8;`
  - `pub const DEFAULT_MIN_SECONDS: f64 = 0.1;`
  - `#[derive(Clone, Copy, PartialEq, Eq, Debug)] pub enum FinderError { Silent, RangeTooShort, RangeTooLong, BadSettings, Cancelled }`
- Produces, in `loop_finder::steady`:
  - `#[derive(Clone, Copy, PartialEq, Eq, Debug)] pub enum RangeKind { Selection, Steady, NoSteadyPart }`
  - `#[derive(Clone, Copy, PartialEq, Eq, Debug)] pub struct SearchRange { pub first: usize, pub last: usize, pub kind: RangeKind }`, with both ends inclusive.
  - `pub fn steady_range(audio: &[Vec<f32>], rate: u32) -> Option<SearchRange>`:
    - the kind is `Steady`, or `NoSteadyPart` for the fallback;
    - `None` for empty audio or silence (every level step below −120 dB).
  - `pub fn search_range(audio: &[Vec<f32>], rate: u32, selection: Option<(usize, usize)>, trim: (usize, usize)) -> Result<SearchRange, FinderError>`:
    - takes the selection (either order) or the steady part, intersected with `trim` (Start..End);
    - a selection longer than 60 s is `RangeTooLong`;
    - a steady part longer than 60 s keeps its last 60 s;
    - an empty intersection is `RangeTooShort`;
    - silence is `Silent`.
- **The rule:**
  - Take RMS levels in 50 ms steps, energy summed over channels.
  - The reference level is the median of the second half.
  - Smooth with a centred running median 0.5 s wide.
  - The end is the last step whose smoothed level is at least `reference − 3 dB`.
  - The start is the first step from which every smoothed level up to the end lies within ±3 dB of the reference.
  - The steady part counts as found when it is at least `max(0.25 s, 20 % of the sound)` long. Otherwise the result is the middle 60 % (20 %..80 %) with `NoSteadyPart`.
  - The spec's "about 6 dB" became 3 dB, so the fade test below can meet its 100 ms bound.

### Task 2: Seam measures, quality and score

**Files:**
- Create: `crates/limewave-core/src/loop_finder/measure.rs` (registered in `mod.rs`)

**Interfaces:**
- Produces, in `loop_finder::measure`, all re-exported from `loop_finder`:
  - `#[derive(Clone, Copy, PartialEq, Eq, PartialOrd, Ord, Debug)] pub enum Quality { Seamless, Good, Fair, Rough }`. The order is best first.
  - `#[derive(Clone, Copy, PartialEq, Debug)] pub struct SeamMeasures { pub click: f32, pub tone: f32, pub matching: f32 }`.
  - `#[derive(Clone, Copy, PartialEq, Debug)] pub struct Natural { pub d2: f32, pub flux: f32 }`: the material's own change over the range.
  - `pub fn natural_change(audio: &[Vec<f32>], first: usize, last: usize, rate: u32) -> Natural`:
    - `d2` is the median, over the range, of the second-difference energy summed over channels;
    - `flux` is the median RMS-dB band difference between consecutive non-overlapping tone frames.
    - Both are floored at a tiny positive value.
  - `pub fn seam_measures(audio: &[Vec<f32>], loop_start: usize, loop_end: usize, rate: u32, natural: &Natural) -> SeamMeasures`, for a forward loop:
    - **`click`:** the squared difference between the spliced second differences at the join (the two values that straddle `x[e] → x[s]`) and the true continuation's second differences at the same place (using `x[e+1]` and `x[e+2]`), summed over channels, divided by `natural.d2`.
      - If `e + 2` is past the end of the audio, compare with the start side's own lead-in (`x[s−2]`, `x[s−1]`, `x[s]`, `x[s+1]`) instead.
      - 0 means the join changes nothing.
    - **`tone`:** the band levels are third-octave energies from 50 Hz up to Nyquist, in dB with a −120 dB floor, energy summed over channels, from a tone frame of `tone_frame(rate)` samples (2,048 at 44,100 Hz; 46 ms rounded to a power of two).
      - Compare the frame ending at `e + 1` with the frame ending at `s`.
      - Where both exist, also compare the frame starting at `e + 1` with the frame starting at `s`.
      - The RMS-dB differences are averaged and divided by `natural.flux`. 0 means identical.
    - **`matching`:** the normalised correlation of ±`M` frames around the join, with `M = round(0.005 · rate)`: `x[e+1−M..e+1+M]` against `x[s−M..s+M]`.
      - Both sides are clipped to the same available lengths at the edges of the file.
      - Per-channel dot products are summed and divided by `sqrt(Σ energies · Σ energies)`.
      - It is 0 when the context is silent.
  - `pub fn quality(m: &SeamMeasures) -> Quality`. The first row that all three measures meet wins; these are starting values, and Task 5 tunes them:

    | Quality | click ≤ | tone ≤ | matching ≥ |
    |---|---|---|---|
    | Seamless | 0.1 | 0.25 | 0.995 |
    | Good | 1.0 | 0.75 | 0.95 |
    | Fair | 4.0 | 1.5 | 0.7 |
    | Rough | otherwise | | |

  - `pub fn score(m: &SeamMeasures) -> f32`: `click.ln_1p() + tone + 4.0 * (1.0 − matching)`. Lower is better.

- [ ] **Step 1: Write the failing tests** in `measure.rs`.
  - `an_exact_repeat_is_seamless`:
    - stereo noise built from a 30,870-frame tile (0.7 s) repeated 4 times, a different tile per channel;
    - a loop `30_870..=92_609` has `click < 1e-6`, `tone < 1e-3` and `matching > 0.9999`, and is `Seamless`.
  - `a_hard_jump_is_rough`: in a 220 Hz sine, a loop from a crest to a trough is `Rough`, with `click > 4.0`.
  - `noise_splices_are_never_better_than_fair`: for 200 seeded random `(s, e)` pairs in 3 s of white noise, `quality(..) >= Quality::Fair`.
  - `out_of_phase_stereo_scores_like_mono`: the repeat tile with `R = −L` gives the same `matching`, within 1e-6, as mono `L`.
  - `a_seam_broken_in_one_channel_is_not_seamless`: the exact-repeat signal with the R channel's start side replaced by fresh noise is not `Seamless`.
  - `a_loop_ending_at_the_last_frame_is_measured`: the exact-repeat loop ending at `len − 1` gives finite measures, with no panic.
  - `quality_thresholds`: hand-built `SeamMeasures` on either side of each table boundary give the expected word.

### Task 3: `find_loops` with a kept loop end

**Files:**
- Create: `crates/limewave-core/src/loop_finder/search.rs`
- Modify: `crates/limewave-core/src/loop_finder/mod.rs`

**Interfaces:**
- Consumes: `SearchRange` (Task 1); `natural_change`, `seam_measures`, `quality`, `score` (Task 2).
- Produces, in `loop_finder`:
  - `#[derive(Clone, Copy, PartialEq, Eq, Debug)] pub enum Direction { Forward, Backward }`
  - `#[derive(Clone, Debug, PartialEq)] pub struct FinderSettings { pub range: (usize, usize), pub keep_end: Option<usize>, pub min_len: usize, pub max_len: Option<usize>, pub preference: f32, pub direction: Direction, pub max_candidates: usize }`
  - `#[derive(Clone, Debug, PartialEq)] pub struct LoopCandidate { pub loop_start: usize, pub loop_end: usize, pub score: f32, pub quality: Quality, pub measures: SeamMeasures, pub period: Option<f32> }`
    - `impl LoopCandidate { pub fn len(&self) -> usize; pub fn cycles(&self) -> Option<f32> }`. `cycles` is the length divided by the period.
  - `pub fn find_loops(audio: &[Vec<f32>], rate: u32, settings: &FinderSettings, cancel: &AtomicBool) -> Result<Vec<LoopCandidate>, FinderError>`
- **Settings rules:**
  - The range is inclusive.
  - `keep_end` may lie past `range.1`; starts are searched in `range.0 ..= keep_end + 1 − min_len`.
  - `min_len > max_len` is `BadSettings`.
  - A range (or kept-end span) shorter than `min_len`, or shorter than one tone frame, is `RangeTooShort`.
  - A range longer than 60 s is `RangeTooLong`.
  - A silent range is `Silent`.
  - `cancel` is checked between candidates and stages. When it is set, the result is `Err(Cancelled)`.
- **Kept-point search, in `search.rs`:**
  - `fn starts_for_end(audio, end, span, opts) -> Vec<usize>`:
    - the reference is up to 1,024 frames before `end + 1`, plus up to 1,024 frames after it where the file has them;
    - it is FFT-correlated against every start in the span, normalised per position with prefix sums and summed over channels as in `pitch.rs`;
    - it returns up to 48 local maxima, at least 50 ms apart.
  - `fn ends_for_start(..)` is the mirror image, used for backward loops.
- **Ranking, in `mod.rs`, shared with Task 4:**
  - `final = score(m) − 0.15 · (preference − 0.5) · 2 · (len / range_len)`, so 0.5 is neutral.
  - Sort ascending. Ties go to the earlier start, then the shorter length.
  - **Whole multiples:** a candidate whose length is `k ≥ 2` times another's (±0.1 %), with a `final` no better than that one's, moves to directly after it.
  - **Duplicates:** two candidates are the same when their lengths differ by less than 1 % and their starts by less than 50 ms, or when both are `Seamless`. Only the better one is kept.
  - Truncate to `max_candidates`.
- **Backward:** reverse a copy of the audio and map the range. Index `i` becomes `n − 1 − i`.
  - A kept loop end becomes a kept *start* in the reversed audio, so the search uses `ends_for_start`.
  - Results map back with `loop_start = n − 1 − e'` and `loop_end = n − 1 − s'`.
- **Period:** `pitch::character(audio, range.0, range.1, rate, 0.6).period`, the same for every candidate.

  - `keep_end_finds_whole_tiles`:
    - with `keep_end = Some(len − 11)` (the end 10 frames before the end of the file), the first candidate's `loop_end == len − 11`;
    - `(loop_end + 1 − loop_start) % T == 0`;
    - it is `Seamless`.
  - `the_shorter_repeat_ranks_first`: in the same search, a candidate one tile long ranks before any candidate two tiles long.
  - `keep_end_at_the_last_frame_works`: `keep_end = Some(len − 1)` returns `Ok` with at least one candidate.
  - `a_range_from_frame_zero_works`: `range = (0, len − 1)` with `keep_end` set returns `Ok`.
  - `limits_are_obeyed`: with `min_len = 40_000` and `max_len = Some(70_000)`, every candidate lies inside the range and every length is within the limits.
  - `no_duplicates`: no two candidates match the duplicate rule.
  - `settings_errors`:
    - `min_len > max_len` gives `BadSettings`;
    - a range of 100 frames gives `RangeTooShort`;
    - a 61 s range gives `RangeTooLong`;
    - silence gives `Silent`;
    - a pre-set `cancel` flag gives `Cancelled`.
  - `backward_keep_end`: the reversed exact-repeat signal, searched `Backward` with a kept loop end, keeps `loop_end` and gives a whole-tile length, `Seamless`.
  - `deterministic`: two runs give equal `Vec`s.

### Task 4: Whole-range search

**Files:**
- Modify: `crates/limewave-core/src/loop_finder/search.rs` and `mod.rs`

**Interfaces:**
- Consumes: everything from Tasks 1–3.
- Produces: `find_loops` handles `keep_end: None`. The public API is unchanged.
- **Method:**
  1. **Coarse frames:** 2,048 samples (scaled as `tone_frame`), hop 512, with third-octave band levels in dB as in Task 2.
  2. **Diagonal walk:**
     - for each lag `L` (in hops) within `min_len..=max_len`, and for each frame pair `(i, i + L)` in the range, the distance is the RMS-dB difference averaged over frames `i−4..=i+4` against `i+L−4..=i+L+4` (clipped at the edges);
     - it runs along each diagonal with a running sum, so memory stays O(frames);
     - keep the best 48 pairs, distinct by more than 8 frames in start or in lag.
  3. **Refine:**
     - for each pair, `e = (i + L)·hop − 1`;
     - slide `s` through `i·hop ± hop` and maximise the same correlation as `starts_for_end`, computed directly over the ±1 hop window.
  4. Measure, rank and de-duplicate as in Task 3. Check `cancel` once per lag diagonal.

- [ ] **Step 1: Write the failing tests** in `mod.rs`:
  - `whole_range_finds_the_tile`: on the exact-repeat signal with `range` from `search_range`, the first candidate's length is a multiple of `T`, its splice error (`max |x[s+k] − x[e+1+k]|` for `k < 256`) is below 1e-3 (−60 dB), and it is `Seamless`.
  - `a_tone_with_vibrato_loops_cleanly`:
    - 3 s of a 220 Hz tone at 44,100 Hz with 8 equal harmonics and 2 Hz vibrato of ±5 cents;
    - the first candidate has `measures.click <= 1.0`;

    - it computes `search_range(&s.processed, s.rate(), selection, (e.start, e.end))`. On `Err`, it stores `range_error` and starts nothing;
    - the direction is `Backward` when the loop mode is Backward, else `Forward`; Ping-pong never gets here;
    - `keep_end` is `Some(e.loop_end)` only when `prefs.keep_end` is set and the loop is on;
    - it converts seconds to frames at `s.rate()`;
    - it copies `s.processed` into the job;
    - it cancels any running job first.
  - `pub fn cancel_search(s: &mut Session)`: sets the flag and drops the job.
  - `pub fn poll_search(s: &mut Session, block: bool)`: takes a finished result, waiting for it when `block`, into `result`, and clears `selected`.
  - `pub fn is_searching(s: &Session) -> bool`.
  - `pub fn is_stale(s: &Session) -> bool`: true when `result.audio_version != s.audio_version`.
  - `pub fn candidate_edit(s: &Session, c: &LoopCandidate) -> Option<EditState>`:
    - returns the current edit with the candidate's points, Forward when the loop was Off, and the crossfade clamped to `max_crossfade()`;
    - returns `None` when the result is stale or the candidate lies outside the current `start..=end`.
  - `pub fn preview_candidate(s: &mut Session, index: usize, engine: Option<&AudioEngine>)`: `set_preview(candidate_edit(..)?)` and `selected = Some(index)`.
  - `pub fn end_preview(s: &mut Session, engine: Option<&AudioEngine>)`: `cancel_preview` and `selected = None`.
  - `pub fn use_candidate(s: &mut Session, index: usize, engine: Option<&AudioEngine>)`: `cancel_preview`, then `apply(candidate_edit(..)?)`. It is one history entry.
- **`Session::cancel_preview`:** clears `preview`, `preview_held` and `last_preview_push`, then `refresh(engine)`, so the rendered audio and the engine go back to the current edit. The history is untouched.
- **Every frame**, for the selected session:
  - `poll_search(s, false)`;
  - if `selected` is set but `s.preview` no longer equals that candidate's edit (an undo, a marker drag, a stale result), set `selected = None` without touching the preview.
- **Test hook:** `wait_for_renders` also blocks on the selected session's finder job (`poll_search(s, true)`).
