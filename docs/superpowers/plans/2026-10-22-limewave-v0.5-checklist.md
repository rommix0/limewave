# Limewave v0.5: release checklist

Status key: **verified (how)**, **covered by automated test (name)**, or **NOT verified: needs a human (what to do)**.

This release adds SFZ instruments: opening, editing, auditioning, building and saving them. The rows below are the spec's §10.3 manual checks and the release checks for the new key map and save dialog. None of them has been run by hand yet, so every row is **NOT verified** until you have tried it.

They are written for `samples/RSB 501-01` (local only, never committed). It holds three instruments that share 16 mono WAVs at 30 kHz and 15 kHz, ripped from an old hardware sampler:

- `E.Piano 1 mp.sfz`: 10 regions.
- `E.Piano 1 vm.sfz`: 20 regions in two layered groups.
- `E.Piano 8vb.sfz`: 20 regions, with `transpose`.

Run the app with `cargo run --release -p limewave`. Turn **Audition** on to play from the computer keyboard.

## Manual checks on `samples/RSB 501-01`

### Opening and playing

- [ ] **Open each instrument.** Use **Open file…** for `E.Piano 1 mp.sfz`, then close it (**Close instrument**) and click `E.Piano 1 vm.sfz` and `E.Piano 8vb.sfz` in the folder's file list. Expected: the region list shows 10, 20 and 20 regions (the 20-region ones in two groups), no row says "missing", and the key map shows a box per region.
- [ ] **Play across the keyboard.** For each instrument, play from C1 up to C7 on the computer keyboard, the on-screen keys or a MIDI keyboard. Expected: every covered key sounds, at the right pitch (no octave jumps between neighbouring regions), the boxes of the sounding regions light up, and keys with no box (hatched) are silent. In `E.Piano 8vb` the sound is transposed as the instrument says.
- [ ] **Velocity layers in `E.Piano 1 vm`.** Set the key map's **Velocity** to 20, play a key, then 120 and play the same key. Expected: both layers sound (the two groups overlap on the same keys, so both play together), and a MIDI keyboard's own velocity changes the level.
- [ ] **Tune 14 shows as -14 cents.** In `E.Piano 1 mp`, select the `EP A1 mp.wav` region (its `tune` is 14). Expected: the Tuning section shows a fine tune of -14 cents. Change nothing and look at the region and file dots: nothing is marked unsaved just because you opened it.

### Editing

- [ ] **Shared sample.** In `E.Piano 1 mp`, select a region that uses `EP A7 mp.wav` (it is used by two regions; the other shared WAV is `EP A1 mp.wav`). Expected: the Loop section says "Shared by 2 regions". Move the loop end, then play a key from each of the two regions. Expected: both regions' sound changes with the loop, and both rows show an unsaved dot.
- [ ] **Edit a key range by dragging a box edge.** In **Keys × velocity**, drag the right edge of one region's box one or two keys. Expected: the Keys field in the inspector follows, the edge snaps to whole keys and cannot cross the other edge, and one Ctrl/Cmd+Z puts it back. Also drag a top edge to change the velocity range. Right-drag across the keyboard keys to set the selected region's key range; a right-click without dragging still sets the root key.
- [ ] **Auto-map and Fill gaps.** Select a region, widen then shrink a few key ranges until there are gaps, and press **Fill gaps**. Expected: gaps close with no range shrinking, and the hatching goes. Press **Auto-map from root keys**. Expected: the group's ranges are rebuilt halfway between neighbouring root keys, from key 0 to key 127, and velocity ranges are unchanged. Each button is one undo step.
- [ ] **Undo order.** Move a key range, then move a loop marker in the same region. Press Ctrl/Cmd+Z once, then again. Expected: the marker move is undone first, then the key range; Ctrl/Cmd+Shift+Z redoes them in the opposite order.
- [ ] **Region volume, envelope and one-shot.** Lower the region's **Volume** by 12 dB and play it. Set a long attack and release. Set **Playback** to **One-shot** and release a key early. Expected: the level drops, the attack and release are heard, and the one-shot plays to the end after you let go. **Stop** silences it. Set **Sustain loop** on a looped region and release: it plays on past the loop end.
- [ ] **Other settings.** Open **Other settings (kept as written)** on a region. Expected: the opcodes Limewave does not edit (filter, LFO and so on) are listed read-only with where each comes from.
- [ ] **Add and delete.** Open the **Unassigned WAVs** section and press **Add** on a row, then press **Add group**, then select the new region and press **Delete region**. Expected: the region appears in the selected group, and deleting it returns the WAV to Unassigned. Ctrl/Cmd+Z undoes each step.

### Saving

- [ ] **Save to a new folder and reopen it.** Make an edit in `E.Piano 1 mp` and press **Save as…** with **SFZ instrument** and **New folder** chosen. Expected: a `limewave` folder appears next to the instrument with the `.sfz` and a `Samples` folder holding every WAV, the instrument is reopened from there with the same region selected, and the unsaved dots are gone. Close it, open the saved `.sfz` again and play it: it sounds the same as the edited instrument. Open the original `.sfz` and check that it is unchanged.
- [ ] **Overwrite originals.** Copy `samples/RSB 501-01` to a scratch folder first. Edit a loop and a key range, then save with **Overwrite originals**. Expected: the `.sfz` and each changed WAV are replaced, each with a numbered `.bak` beside it (`.1.bak` and so on if one exists), and the unchanged WAVs are left alone.
- [ ] **`smpl` checkbox off and on.** Save a copy with **Also write loop and root key into each WAV (smpl)** off, then another with it on. Expected: with it off, a WAV opened on its own shows the loop and root key it had before; with it on, it shows the instrument's values (root key from `pitch_keycenter`, fine tune the opposite of `tune`).
- [ ] **Individual WAV files.** Edit a loop, press **Save as…**, choose **Individual WAV files** and save. Expected: the WAVs are written, but the instrument still shows as unsaved, and Close instrument still asks about unsaved changes.
- [ ] **Unsaved prompt on close.** Make an instrument edit only (a key range, no sample edit) and press **Close instrument**, or open another file or folder. Expected: the unsaved-changes prompt appears; Cancel keeps everything as it was.

### New instruments

- [ ] **New instrument from a folder of WAVs.** Open the folder `samples/RSB 501-01/Samples` and press **New instrument** at the top of the file list. Expected: an unsaved, untitled instrument with one region per WAV, key ranges laid out from the root keys, and the WAVs unchanged. Play across the keyboard, then **Save** it. Expected: the save-file picker opens, `.sfz` is added to the name, the samples sit beside it at paths relative to it, and the instrument reopens from disk.
- [ ] **Load a saved instrument in a sampler you have (optional).** Open a saved `.sfz` in a sampler of your choice. Expected: the regions, key ranges, velocity layers, loops and tuning agree with what Limewave played. Test both with the `smpl` checkbox off and on.

### Window

- [ ] **900 px window.** Make the window 900 px wide with an instrument open. Expected: the key map's buttons (**Auto-map from root keys**, **Fill gaps**, **Velocity** and the view toggle) are all reachable, and nothing overlaps or is cut off.

## Known limitations

These are known and deliberately left for a later version.

- `#include` is not supported; an instrument that uses it is refused.
- Not auditioned (kept on save): filters, pitch and filter envelopes, LFOs, pan and width, round robins, crossfaded layers, release triggers, keyswitches, CC modulation and effects.
- Key-map edits write note names only where the existing value is a note name.
- Only one instrument can be open at a time.
- WAV names that cannot be written as an SFZ value (for example a space followed by `name=`, or a name containing `<`, `//` or `$`) are left out of new instruments.
