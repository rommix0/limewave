# Limewave v0.6 Sample-Rate Conversion Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** **Effects ▸ Change sample rate…** converts the whole sample to any typed rate from 1,000 to 768,000 Hz. Pitch and length are kept, and the conversion is one undoable step.

**Architecture:**
- Core gets a windowed-sinc resampler (`dsp/resample.rs`) and a new effect step, `Op::Resample`. Like `Op::Splice`, the step carries audio rendered once, so replaying it is cheap.
- The file's rate becomes a function of its effect list, `rate_after`. Every frame position is scaled through the step by `resample_map`.
- Save, SFZ write-back and the app read the effective rate.
- The app adds a modal dialog that renders on the existing `render_worker`.

**Tech Stack:** Rust workspace (`limewave-core`, `limewave`), eframe/egui 0.37, egui_kittest. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-10-22-limewave-sample-rate-design.md`

## Global Constraints

- No third-party program or product names anywhere: code, comments, UI text, docs or commit messages. Say "an old hardware sampler".
- Permissive licences only; `cargo deny check licenses` stays clean. No new dependencies.
- Typed rate range: `MIN_RATE = 1_000`, `MAX_RATE = 768_000`, in whole hertz.
- Frame scaling rounds to the nearest frame, with halves rounded up. The end-of-file position maps to the new length.
- Every task ends with `cargo fmt --all`, `cargo clippy --workspace --all-targets -- -D warnings` and `cargo test --workspace` all clean. Commit only that task's files, and never `session_memory.json`.
- Comment density and naming must match the surrounding code (doc comments on every pub item, British spelling in UI text and docs).
- Version: `0.6.0`.

## Review Focus

1. **A tiny target rate on a long or high-rate file** (96,000 to 1,000 Hz). The loop can shrink below 2 frames, and markers can collide. Expect the loop to turn off and the markers to clamp, with no panic. Test it in Task 2.
2. **Converting a file that already has a tail or spectrum loop.** The lime tint has to follow the scaled audio. Test it in Task 2 (`generated_ranges`).
3. **Undo across a conversion.** Rate, ruler, crossfade milliseconds, selection and play-from must all return. Test it in Task 5.
4. **Rate text that is not a clean number:** leading zeros, spaces, commas, a value above `u32::MAX`, or an empty field. The field must only accept digits and the dialog must never panic. Test it in Task 6.
5. **An instrument sample converted and then saved.** Every region using it must get scaled frame opcodes, including non-followers, and the tuning must not change. Test it in Task 4.

- [ ] **Step 1: Write the failing tests** in `resample.rs`'s test module. Use local helpers:
  - `sine(freq, rate, secs, amp)` generates a test tone.
  - `rms(x)` is taken over the middle half of the output, so the edges are excluded.
  - `goertzel_db(x, freq, rate)` measures the level of one frequency.

  ```rust
  #[test] fn length_rounds_to_the_nearest_frame() {
      assert_eq!(resampled_len(44_100, 44_100, 31_250), 31_250);
      assert_eq!(resampled_len(3, 2, 1), 2);       // 1.5 rounds up
      assert_eq!(resampled_len(0, 44_100, 8_000), 0);
  }
  #[test] fn a_tone_keeps_its_pitch_and_level_through_odd_rates() {
      // 1 kHz at 44.1k -> 31,250 -> 13,000 -> 96,000: still 1 kHz, level within 0.1 dB.
      let x = vec![sine(1000.0, 44_100, 0.5, 0.5)];
      let a = resample(&x, 44_100, 31_250);
      let b = resample(&a, 31_250, 13_000);
      let c = resample(&b, 13_000, 96_000);
      let want = 0.5 / 2f32.sqrt();
      assert!((20.0 * (rms(&c[0]) / want).log10()).abs() < 0.1);
      assert!(goertzel_db(&c[0], 1000.0, 96_000) > goertzel_db(&c[0], 1100.0, 96_000) + 60.0);
  }
  #[test] fn downsampling_removes_what_the_new_rate_cannot_hold() {
      // 10 kHz is above 6.5 kHz, the Nyquist of 13 kHz: nothing may fold back.
      let y = resample(&[sine(10_000.0, 44_100, 0.5, 0.5)], 44_100, 13_000);
      assert!(20.0 * rms(&y[0]).max(1e-12).log10() < -90.0);
  }
  #[test] fn the_passband_reaches_ninety_percent_of_the_lower_nyquist() {
      // 0.9 x 6.5 kHz = 5.85 kHz survives 44.1k -> 13k within 0.1 dB.
      let y = resample(&[sine(5_850.0, 44_100, 0.5, 0.5)], 44_100, 13_000);
      assert!((20.0 * (rms(&y[0]) / (0.5 / 2f32.sqrt())).log10()).abs() < 0.1);
  }
  #[test] fn constant_audio_stays_constant_to_the_edges() {
      let y = resample(&[vec![0.5; 1000]], 44_100, 48_000);
      assert!(y[0].iter().all(|v| (v - 0.5).abs() < 1e-4));
  }
  #[test] fn channels_and_determinism() {
      let x = vec![sine(440.0, 22_050, 0.1, 0.3), sine(660.0, 22_050, 0.1, 0.3)];
      let a = resample(&x, 22_050, 44_100);
      assert_eq!(a.len(), 2);
      assert_eq!(a, resample(&x, 22_050, 44_100));
      assert_eq!(resample(&x, 22_050, 22_050), x);
      assert_eq!(resample(&[Vec::new()], 44_100, 8_000), vec![Vec::<f32>::new()]);
  }
  ```

- [ ] **Step 2: Run** `cargo test -p limewave-core --lib dsp::resample`. Expected: FAIL to compile (`resample` undefined).

- [ ] **Step 3: Implement.** The algorithm, which the signature does not determine:
  - **Cutoff** in input-sample units: `fc = 0.475 * min(1, to / from)`.
  - **Kernel:** a Kaiser-windowed sinc with `ZEROS = 64` zero crossings per side and `beta = 10.0`. Tabulate it once in zero-crossing units, as `g(u) = sinc(u) * kaiser(u / ZEROS)` for `u` in `[0, ZEROS]` at `TABLE_STEPS = 1024` points per unit. Read it with linear interpolation: `h(t) = g(|2·fc·t|)`.
  - **Output frame n** sits at input position `x = n * from / to`. Compute `n * from` as u64 and split it into an integer part and a fraction, so long files don't drift.
  - Sum `in[clamp(k, 0, len-1)] * h(x - k)` for `k` over `ceil(x - W) ..= floor(x + W)`, where `W = ZEROS / (2·fc)`. Clamping the index holds the edge frames.
  - Divide by the sum of the weights used, so DC gain is exactly 1.
  - Compute in f64 per output and store as f32.

### Task 2: The Resample effect step and the effective rate

**Files:**
- Modify: `crates/limewave-core/src/effects.rs`, `crates/limewave-core/src/edit.rs`

**Interfaces:**
- Consumes: `resample`, `resampled_len`, `MIN_RATE` and `MAX_RATE` from Task 1.
- Produces:
  - `pub struct Resample { pub from: u32, pub to: u32, pub audio: Vec<Vec<f32>> }`, with `#[derive(Clone, PartialEq, Debug)]`, in `effects.rs`.
  - `Op::Resample(Arc<Resample>)`. `first..=last` is the whole step input.
  - `pub fn rate_after(file_rate: u32, effects: &[AppliedEffect]) -> u32`: the `to` of the last Resample step, else `file_rate`.
  - `pub fn resample_map(effects: &[AppliedEffect], f: usize, input: usize) -> usize`, which maps a frame of a file of `input` frames through only the Resample steps of `effects`:
    - each step scales by `round(f * to / from)`;
    - `f == input` maps to the new length;
    - anything else is clamped to the new length − 1.
  - `pub fn resample_edit(e: &EditState, processed: &[Vec<f32>], to: u32, file_rate: u32, original_frames: usize) -> Option<EditState>`, in `edit.rs`:
    - it returns `None` when `to` is the current rate (`rate_after(file_rate, &e.effects)`), is out of range, or `processed` is empty;
    - otherwise it returns `e` with a Resample step pushed, rendered by `resample(processed, from, to)`, with these scaled through the step: Start, End, loop start and loop end (by the frame rule); the crossfade (by `round(c * to / from)`);
    - the result is passed through `clamped(original_frames)`.
- Behaviour every existing function must get:
  - `apply_effect` swaps in `audio`, skipping it on a channel-count mismatch, like Splice.
  - `output_frames` returns the audio length.
  - `changes_length` is true.
  - `map_frame`, `map_range` and `generated_ranges` scale through the step.
  - `EditState::clamped` keeps a Resample step whose range fits its input, the same rule as Splice.
  - Every other exhaustive `match` on `Op` treats it like a whole-file Splice; the compiler lists them.
