# Limewave v0.2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Limewave v0.2 on top of the working v0.1. It adds:
- marker labels as drag handles
- right-click a key to set the root key
- backward loops
- playback cursors
- an ADSR audition envelope
- selection with selection-based actions
- cheap effects
- trims based on the loop points
- saves that keep every chunk Limewave doesn't edit

**Architecture:** Effects are replayable operations stored in the per-file `EditState`, so undo, preview and save all keep working the way v0.1 does. The core library gets new pure modules `effects` and `cue` and extends `edit`, `render`, `save`, `wav` and `dsp::zerocross`. It stays free of UI and device code and holds most tests. The app's `Session` caches the processed audio (original audio → effects). The engine gets an envelope, backward loops, a play-range command and a lock-free cursor feed. The UI adds a selection, Edit and Effects menus, effect dialogs and an Envelope section.

**Tech Stack:** Rust (edition 2024), eframe/egui 0.37 (now with the `persistence` feature), cpal 0.18, midir 0.11, rfd 0.17, arc-swap 1.9, rtrb 0.4, thiserror 2, tempfile 3, egui_kittest 0.37 (dev).

**Spec:** `docs/superpowers/specs/2026-10-20-limewave-v0.2-design.md` ("v0.2 §N"). It builds on `docs/superpowers/specs/2026-10-19-limewave-design.md` ("v0.1 §N"). Read both before starting any task.

## Global Constraints

- Licence `MIT OR Apache-2.0`. Dependencies must be permissively licensed; `cargo deny check licenses` stays clean.
- Never name other commercial audio products in code, comments, UI text, docs or commit messages.
- Platforms: Windows, macOS, Linux. No platform-specific code beyond what crates handle.
- The audio callback never allocates, locks or blocks.
- Library code never panics on bad input. Errors are values, and lenient fixes are reported as warnings.
- `smpl` loop end is inclusive. Loop types: 0 forward, 1 ping-pong, 2 backward; types 3 and up are kept until the loop is edited.
- Every effect keeps the frame count. Channel tools change only the channel count (v0.2 §3).
- Pipeline: original audio → effects in order → crossfade → trim (v0.2 §3, §4.7).
- With no selection: Gain, Normalize, Invert and Remove DC process the entire file, while Normalize and Remove DC *measure* only Start…End. Fades and Reverse work on Start…End. Channel tools and auto-trim always work on the whole file (v0.2 §4.7).
- Values from the spec:
  - Effects:
    - Gain range −48…+48 dB.
    - Normalize target defaults to −0.1 dBFS.
    - Auto-trim threshold defaults to −60 dBFS.
  - Trims: trim padding defaults to 16 frames, settable to 0.
  - Envelope:
    - Defaults: attack 2 ms, decay 0 ms, sustain 100 %, release 30 ms.
    - Ranges: times 0…10 000 ms, sustain 0…100 %.
- A save with no edits gives back the original bytes, apart from `ISFT` (v0.2 §4.8).
- The version becomes `0.2.0`, so the software tag reads `Limewave 0.2.0` (Task 15).
- Colours as in v0.1: panel `#1b1e25`, wave `#5fb3ff`, loop `#ffc400`, start `#4ade80`, end `#f87171`, crossfade `#c084fc`, neon `#22d3ee`, lime `#a3e635`.
- Every task ends with these clean: `cargo fmt --check`, `cargo clippy --workspace --all-targets --all-features -- -D warnings` and `cargo test --workspace --all-features`.

## Review Focus

These are the inputs and failure modes the spec implies but doesn't spell out, most likely to bite a user first. Each one has a pinned test in the task that owns the code.

1. **A selection dragged right to left, or past the waveform's edges.** It must become an ordered range clamped to the file. *Task 10: `dragging_right_to_left_gives_an_ordered_clamped_selection`.*
2. **Normalize or Remove DC on silence, or on an empty or one-frame file.** There must be no NaN or infinity, and the effect is simply not applied. *Task 2: `normalize_of_silence_is_not_applied` and `empty_and_one_frame_audio_do_not_panic`.*
3. **Channel tools on a `WAVE_FORMAT_EXTENSIBLE` 24-bit file.** The `fmt ` chunk must be rewritten with the right channel mask, and the saved file must reopen. *Task 4: `extensible_channel_change_rewrites_the_mask`.*
4. **Malformed markers.** This covers a `cue ` chunk whose count claims more points than it holds, and a `LIST/adtl` with a truncated subchunk. Both must be kept byte for byte, with a warning and no panic. *Task 5: `malformed_cue_is_kept_unchanged` and `truncated_adtl_is_kept_unchanged`.*
5. **Undo of a whole-sample reverse while a loop and a crossfade are set.** The markers, the crossfade length and the audio must all be restored exactly. *Task 8: `reverse_whole_and_undo_restore_markers_crossfade_and_audio`.*

**Interfaces:**
- Produces:
  - `LoopMode::Backward` (fourth variant). `EditState::max_crossfade` is unchanged for Backward, so `clamped` keeps the crossfade value.
  - `render::crossfade_region` returns `None` when `loop_mode == Backward`, so `render` leaves the audio untouched.
  - `pub fn seam_data_backward(x: &[f32], loop_start: usize, loop_end: usize, half: usize) -> SeamData` returns the same struct as `seam_data`, in backward playback order:

  - `pub fn loop_crossing(mode: LoopMode) -> Crossing`: Backward gives Downward; everything else gives Upward.

### Task 2: The effects engine

**Files:**
- Create: `crates/limewave-core/src/effects.rs`
- Modify: `src/lib.rs` (`pub mod effects;`), `src/edit.rs` (add `pub effects: Vec<AppliedEffect>` to `EditState`, empty in `default_for` and kept by `clamped`)

**Interfaces:**
- Produces (all in `limewave_core::effects`; all derive `Clone, PartialEq, Debug`, and the enums without data also derive `Copy`):
  - `pub enum FadeCurve { Linear, Exponential, SCurve }`
  - `pub enum Effect { Gain { db: f32 }, Normalize { target_db: f32 }, FadeIn(FadeCurve), FadeOut(FadeCurve), Invert, RemoveDc, Reverse, StereoToMono, SwapChannels, MonoToStereo }`. This is what the user picks.
  - `pub enum Op { Scale(f32), Offset(Vec<f32>), FadeIn(FadeCurve), FadeOut(FadeCurve), Invert, Reverse { mirror_markers: bool }, StereoToMono, SwapChannels, MonoToStereo }`. This is a resolved, deterministic step. Normalize becomes `Scale`; Remove DC becomes `Offset`, holding one value per channel that is added.
  - `pub struct AppliedEffect { pub op: Op, pub first: usize, pub last: usize }`. The range is inclusive.
  - `pub fn plan_effect(effect: Effect, audio: &[Vec<f32>], e: &EditState, selection: Option<(usize, usize)>) -> Option<AppliedEffect>`
    - It applies the range rules from Global Constraints. The selection is clamped to the file and ordered.
    - Channel tools ignore the selection and use `0..=frames-1`.
    - A Reverse with no selection gets `mirror_markers: true`.
    - It returns `None` when:
      - the audio has no frames;
      - Normalize measures a peak of 0;
      - `StereoToMono` or `SwapChannels` is planned on mono;
      - `MonoToStereo` is planned on stereo.
  - `pub fn fade_gain(curve: FadeCurve, t: f32) -> f32`: maps `t` in 0…1 to a gain in 0…1. It is monotonic non-decreasing, and `fade_gain(c, 0.0) == 0.0` and `fade_gain(c, 1.0) == 1.0` exactly. Linear is `t`; the exponential and S-curve formulas are the builder's choice (v0.2 §8), documented in the function's doc comment.
  - Fades over `first..=last`, with `n = last - first + 1` and `t_i = i / (n - 1)` (`t = 1` when `n == 1`):
    - FadeIn multiplies sample `first + i` by `fade_gain(c, t_i)`.
    - FadeOut multiplies it by `fade_gain(c, 1 - t_i)`.
  - `pub fn apply_effect(audio: &mut Vec<Vec<f32>>, a: &AppliedEffect)`
  - `pub fn process(original: &[Vec<f32>], effects: &[AppliedEffect]) -> Vec<Vec<f32>>`
  - `pub fn peak(audio: &[Vec<f32>], first: usize, last: usize) -> f32`: the largest absolute sample value across all channels; 0 for an empty range.
  - `pub fn map_frame(effects: &[AppliedEffect], f: usize) -> usize`: composes the reflections `first + last - f` of every `Reverse { mirror_markers: true }` whose range contains `f`, in order.
  - `pub fn mirror_edit(e: &EditState, first: usize, last: usize) -> EditState`: new loop start `= first + last - old loop_end` and new loop end `= first + last - old loop_start`. Start, End and everything else are unchanged.
  - `pub fn silence_bounds(audio: &[Vec<f32>], threshold_db: f32, e: &EditState) -> Option<(usize, usize)>`: the first and last frame where any channel's absolute value is at least `10^(threshold_db / 20)`. While the loop is on, start is at most `loop_start` and end is at least `loop_end`. It returns `None` when everything is below the threshold.

### Task 4: Saving processed audio

**Files:**
- Modify: `crates/limewave-core/src/save.rs`, `src/wav.rs`

**Interfaces:**
- Consumes: `process`, `map_frame` and `AppliedEffect` (Task 2).
- Produces:
  - `pub fn fmt_with_channels(fmt: &[u8], channels: u16) -> Vec<u8>` in `wav.rs`. It updates:
    - the channel count;
    - block align: `channels × container bytes`;
    - byte rate: `rate × block align`;
    - for an extensible `fmt ` (tag 0xFFFE, at least 24 bytes), the channel mask at bytes 20..24: 1 channel → `0x4`, 2 channels → `0x3`.
  - In `build_wav_bytes`:
    - The audio is `process(&doc.audio, &e.effects)`, then the crossfade is computed on it with `crossfade_region`, then it is trimmed.
    - In `data`, only the frames inside some effect's range or the crossfade region are re-encoded; every other frame keeps its original bytes.
    - When the channel count changed, `data` is fully re-encoded with the new format, and `fmt ` is rewritten with `fmt_with_channels`.
    - Extra `smpl` loops (index 1 and up) are mapped through `map_frame`, then range-filtered and shifted as in v0.1.
    - **Kept `smpl` bytes:** the original `smpl` chunk is copied unchanged when all of these hold:
      - loop mode, points, root and cents equal `doc.initial_edit()`;
      - `e.start == 0`;
      - no `Reverse { mirror_markers: true }` is in `e.effects`;
      - every extra loop lies inside `0..=e.end`.

    - `Adsr::DEFAULT` = `{ 2.0, 0.0, 1.0, 30.0 }`.
    - `pub fn clamped(self) -> Adsr`: times limited to 0…10 000 ms and sustain to 0…1; a NaN field takes its default value.
  - **Envelope:** all stages are linear segments in output frames. *Builder's choice documented here: linear; v0.2 §4.5.*
    - Attack goes 0 → 1, decay goes 1 → sustain, then the level holds at sustain.
    - Release goes from the current level to 0 in `release_ms`, whatever level it starts from.
    - A zero-length stage is skipped.
  - `Voice::new(note: u8, from: usize, buf: &PlayBuffer, device_rate: u32, adsr: Adsr, stop_at: Option<usize>) -> Voice`
    - With `stop_at = Some(to)`, the voice ignores the loop and releases when its position reaches `to`. It then keeps reading forward until the release ends or the audio runs out; it is not stopped at End.
  - `pub fn set_release_ms(&mut self, ms: f32)`, `pub fn level(&self) -> f32` (the current envelope level) and `pub fn position(&self) -> f64`.
  - **Backward loop playback:**
    - The voice plays forward until it passes `loop_end`. It then reflects and plays backward.
    - Below `loop_start` it jumps up by the loop length and keeps going backward.
    - While it plays backward inside the loop, interpolation taps outside the loop wrap modulo the loop length, as for a forward loop.
  - `pub enum Command { NoteOn { note: u8, from: usize }, NoteOff { note: u8 }, AllOff, SetEnvelope(Adsr), PlayRange { note: u8, from: usize, to: usize } }`. It drops `Eq` (it now holds `f32`) and stays `Copy`.
  - `MixerState` holds the current `Adsr`:
    - New voices start with it.
    - `SetEnvelope` replaces it and calls `set_release_ms` on every sounding voice.
  - `AudioEngine::set_envelope(&mut self, a: Adsr)` sends `SetEnvelope(a.clamped())`.
  - Remove `RELEASE_MS`. `AllOff` and `NoteOff` release through the envelope; voice stealing is unchanged.
  - **Releasing voices finish on their own audio** (v0.2 §4.5: switching or closing a file releases instead of cutting):
    - `PlayBuffer` gains `pub source: u64`.
    - `play_buffer(doc_audio, rate, e, source: u64)` gains a matching parameter.
    - `Session` gets `pub source: u64`, assigned from a process-wide `AtomicU64` counter in `Session::new`, so a session rebased after a save gets a new id.
    - The empty buffer uses source 0.
    - Each voice records the source it started with.
    - The audio callback keeps two `Arc<PlayBuffer>`s, `current` and `previous`, taken with `ArcSwap::load_full`:
      - When the loaded buffer's source differs from `current.source`, `previous` becomes the old `current`. Otherwise `current` is simply replaced, so live edits are still heard.
      - Voices render from the buffer whose source matches theirs. A voice whose source matches neither buffer is dropped.
    - The callback never frees a buffer, because the UI's `retired` list still holds a reference to every buffer it swapped out.
