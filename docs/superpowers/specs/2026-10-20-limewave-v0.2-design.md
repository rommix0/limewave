# Limewave v0.2: design

Status: draft for approval · 2026-10-20

This document specifies **version 0.2**. It builds on the v0.1 design (`2026-10-19-limewave-design.md`, "the v0.1 spec"), which stays the reference for everything not changed here. Where the two disagree, this document wins. Section references like "v0.1 §6.6" point into the v0.1 spec.

## 1. Intent

v0.1 was tested by hand and works as a hand-editing loop tool. v0.2 makes everyday editing faster and more like a normal audio editor, without losing what makes Limewave a sample-preparation tool:

- markers and the keyboard are quicker to use (drag by the label, right-click a key to set the root);
- you can see where playback is;
- notes have a proper amplitude envelope (ADSR), the standard every synthesizer and sampler uses, and the one SFZ instruments will need later;
- loops can play backward;
- a small set of cheap, standard audio effects, applied to a selection or the whole sample;
- quick trims based on the loop points and on a selection;
- saving no longer throws away metadata Limewave doesn't show.

The guiding rule for metadata stays: **`smpl` is the only chunk Limewave shows and edits.** Everything else in a file is kept safe and saved again, but not displayed.

## 2. Goals, non-goals, anti-goals

### Goals for v0.2

1. **Marker labels are drag handles.** Start, Loop start, Loop end and End can be dragged by their flag labels as well as by their lines (§4.1).
2. **Right-click a key to set the root key** on the on-screen keyboard (§4.2). The same gesture will set key ranges in the SFZ milestone.
3. **Backward loop mode**, saved as the standard `smpl` backward loop type and auditioned backward. Not destructive (§4.3).
4. **Keep existing metadata on save**, including cue markers, without showing it (§4.8).
5. **Moving playback cursors**, one per sounding note, in the waveform, the overview strip and the seam view (§4.4).
6. **ADSR amplitude envelope** for audition, replacing the fixed 10 ms release fade (§4.5).
7. **Selection** on the waveform, with Play selection, Set loop to selection and Set Start/End to selection (§4.6).
8. **Cheap effects** applied to the selection, or to the whole sample when nothing is selected: gain, normalize, fade in, fade out, invert polarity, remove DC offset, reverse; plus whole-file channel tools and auto-trim silence (§4.7).
9. **Trim based on loop points**: Trim after loop end, and Crop to loop (§4.9).
10. Smaller additions from the same review: click to set the play-from point, type an exact marker position, set the root key from a MIDI note (§4.1, §4.2, §4.4).

### Non-goals for v0.2

- Showing, adding, moving or renaming cue markers. They are kept, never displayed (§4.8).
- Saving the ADSR envelope into WAV files. WAV has no standard place for it; it becomes per-region SFZ data in the SFZ milestone.
- Resampling, pitch-shifting, time-stretching, filters/EQ, recording. (These were "not planned" in v0.1 and stay out; v0.2 only adds the cheap effects listed above.)
- Applying effects to many files at once.
- SFZ, tails, pitch detection, the classifier, the loop finder (see §6 for the new order).

### Anti-goals (in addition to v0.1 §2)

- **Losing metadata the user didn't touch.** A save with no edits must give back the original file byte for byte, apart from the `ISFT` software tag.
- **Metadata that points at the wrong audio.** Positions stored in kept chunks must follow the audio through trims and reverses (§4.8), and frame counts stored in kept chunks must match the saved audio.
- **Effects that can't be undone** before saving, or an undo that takes noticeably long.
- **New clicks.** The envelope, the cursors and the effects must not introduce clicks or dropouts in audition.

## 3. What changes in the edit model

v0.1 §6.2 kept the original audio unchanged plus a small parameter state. v0.2 keeps that idea and adds two things to the per-file edit state:

- **An ordered list of applied effects** (§4.7). Each entry records the effect, its parameters and the frame range it applied to. The audio shown, played and saved is: original audio → effects in order → crossfade → trim. The list is part of the undo snapshot, so undoing an effect is just popping it; the builder caches the processed audio so it isn't recomputed on every repaint.
- **The loop mode gains `Backward`** (Off / Forward / Ping-pong / Backward).

Not part of the per-file edit state: the selection, the play-from point and the ADSR envelope (session state; the envelope is remembered between runs, §4.5).

**All v0.2 effects keep the frame count unchanged.** Channel tools change the channel count but not the length. This is deliberate: every marker, selection and stored effect range stays valid without remapping. Auto-trim silence and the trim actions move Start/End markers instead of cutting audio, like v0.1 trims.

After a save, the document is rebased onto the saved file exactly as in v0.1 §6.6: the effects list empties (it is now baked into the audio), the crossfade resets, and undo history starts fresh.

## 4. v0.2 specification

### 4.1 Markers

- **Drag by the label.** Each marker's flag label is a grab target, in addition to the line. Pressing on a label grabs that marker exactly as pressing on the line does: same snapping, Shift to disable snap, one undo step per drag. Hovering a line or a label shows a horizontal-resize cursor.
- When two markers' grab areas overlap, the label under the pointer wins over a line; among lines the closest wins (as v0.1).
- **Type an exact position.** Double-clicking a marker's label opens a small number field for that marker's frame position. Enter applies it (one undo step, no snapping, same limits as dragging); Escape cancels. The inspector's numeric loop fields stay.
- Pressing elsewhere on the waveform does **not** move markers; it selects (§4.6).

### 4.2 Keyboard strip and root key

- **Right-click a key** sets the root key to that note. One undo step. Fine tune is unchanged. Left-click still plays the key, as in v0.1.
- Right-click-drag across keys does nothing in v0.2. In the SFZ milestone it will set a region's key range; v0.2 should not give it another meaning.
- **Set root from MIDI:** a button next to the root key field in the inspector arms "learn". The next MIDI note-on (from the connected MIDI device) sets the root key and disarms it; that note also plays as normal. Escape or pressing the button again cancels. Only shown when a MIDI device is connected.

### 4.3 Backward loop

- New loop mode **Backward**, written to `smpl` as loop type 2 (v0.1 §6.5 already reserves it). Reading a type 2 loop now shows Backward instead of "backward loop shown as forward". Unknown loop types (3 and up) keep their v0.1 behaviour (kept until the loop is edited).
- **Playback:** the voice plays forward from its start point to the loop end, then plays the loop region backward: loop end → loop start, then jumps to loop end and continues backward, until the note is released and the envelope finishes. The audio itself is not changed.
- **Seam view:** for a backward loop the seam is the jump from loop start (going backward) to loop end. The seam view shows the audio in playback order around that jump: `…, x[loop_start + 1], x[loop_start]` on the left and `x[loop_end], x[loop_end - 1], …` on the right, with the same faint "what would have come next" underlay as v0.1 (`x[loop_start - 1], …` under the right half). The readout compares the jump with the natural next step in the same way.
- **Zero-crossing snap** for a backward loop uses the v0.1 rule mirrored in time, so that the sample played after the jump continues the slope of the sample before it. *Exact rule and tests are the builder's, as long as a backward loop of exactly `k` periods of a sine snaps to a click-free seam.*
- **Crossfade:** turned off for backward loops in v0.2. The crossfade length and shape controls are disabled while the mode is Backward, nothing is rendered, and the value is kept so switching back to Forward restores it. *My call; a backward-loop crossfade can come later if wanted.*
- The inspector says, in plain words, that some samplers ignore backward loops and play them forward.

### 4.4 Playback cursors and play-from point

- **Cursors:** while any voice is sounding, each voice's current position is drawn as a thin vertical line in the main waveform, the overview strip, and the seam view (when it falls inside the seam view's window). Each voice has its own cursor, so held chords show several cursors moving at their own speeds and directions (ping-pong, backward). A voice's cursor fades out with its release and disappears when the voice ends.
- The audio thread publishes voice positions (in file frames) without allocating, locking or blocking, for example by writing them into atomics or pushing them through a lock-free queue once per audio callback. The UI repaints continuously only while voices are sounding.
- Cursor position may lag the sound slightly; compensating for the output device latency is nice to have, not required. *Builder's choice.*
- **Play-from point:** a single click (press and release without dragging) on the waveform, away from markers, sets the play-from point and clears the selection. It is drawn as a small marker in a neutral colour. The Play button (and its shortcut) plays from the play-from point when one is set, otherwise from Start as in v0.1. Playback from that point then runs into the loop as usual. Keyboard and MIDI notes always start at Start, as a sampler would. Escape clears the play-from point. The play-from point is not saved and is not part of undo.

### 4.5 ADSR envelope

- Every auditioned voice (Play button, Play loop, Play selection, computer keyboard, MIDI, clicking the keyboard strip) has an amplitude envelope: **attack** time, **decay** time, **sustain** level, **release** time.
- Attack ramps from silence to full level; decay falls from full level to the sustain level; the voice holds the sustain level while the key or Play is held; release falls from the current level to silence after key-up or Stop. Releasing during attack or decay releases from the level reached so far, with no jump.
- Curves: attack is linear. Decay and release curves are *the builder's choice*, documented, and should be chosen with an eye to SFZ's own amplitude envelope, which the SFZ milestone will map this onto (`ampeg_attack`, `ampeg_decay`, `ampeg_sustain`, `ampeg_release`).
- Ranges: attack, decay and release 0 ms to 10 s; sustain 0 to 100 %. **Defaults:** attack 2 ms, decay 0 ms, sustain 100 %, release 30 ms. *My call: short enough to sound like the raw sample, long enough that starting mid-sample or stopping doesn't click.*
- A one-shot (loop Off) voice still ends when the sample ends, whatever the envelope says.
- Stopping playback (Stop button, shortcut, closing the file, switching files) releases every voice through its envelope instead of cutting it. Voice stealing (more than 8 voices) may still use a short fixed fade on the stolen voice. *Builder's choice of length.*
- One envelope for the whole session, not per file. It is shown in a small **Envelope** section of the inspector (four value controls, plus a small drawing of the envelope shape if cheap) and remembered between runs. *My call: the SFZ milestone makes it per region; until then a per-file value that silently vanishes on save would be confusing.*
- Changing the envelope while notes sound affects new notes immediately; sounding voices pick up the new release when they are released. *Builder may apply changes to sounding voices too, if click-free.*

### 4.6 Selection

- **Making a selection:** press on the waveform away from markers and labels and drag. The selected range is drawn as a light overlay across all channel lanes. Shift-click extends the selection to the clicked point. Select all (Ctrl/Cmd+A) selects Start…End. Escape clears the selection (and the play-from point).
- With zero-crossing snap on, selection edges snap to upward zero crossings using the same search as loop markers; Shift disables it while dragging, as for markers.
- The selection is a frame range (inclusive). It is session state: not saved, not part of undo, cleared when switching files and after a save.
- **Play selection:** plays the selected range once, from its start, at the root key, through the envelope, without looping. When the voice reaches the selection end it is released: the envelope's release starts there and the voice keeps reading the audio after the selection until the release reaches silence (or the file ends). So it ends the way letting go of a key does, with no click. *My call.*
- **Set loop to selection:** loop start = selection start, loop end = selection end (inclusive), turning the loop on in Forward mode if it was Off (keeping the current mode otherwise). If the selection reaches outside Start…End, Start and End move outward to include it. One undo step. Disabled without a selection.
- **Set Start/End to selection:** Start = selection start, End = selection end. If the loop would fall outside, the action is refused with a short message instead of moving the loop. One undo step. *My call: the selection-based sibling of the loop-point trims in §4.9; it costs almost nothing.*

### 4.7 Effects

**Where they apply:** to the selection when there is one. With no selection, what "the whole sample" means depends on the effect. *My call:*

- **Gain, Normalize, Invert polarity, Remove DC offset:** the **entire file**, including audio outside Start…End. That audio can still be heard or saved: the crossfade reads audio before the loop start, which may lie before Start (v0.1 §6.6), and Start/End can be dragged outward later. Processing it too keeps levels and polarity consistent everywhere, so a crossfade never mixes processed and unprocessed audio. Normalize and Remove DC still *measure* only Start…End (the part that will be saved); the resulting gain or offset is then applied to the entire file.
- **Fade in, Fade out, Reverse:** **Start…End**, so a fade out ends at End, and a reverse flips exactly what will be saved.

Channel tools and auto-trim silence always work on the whole file (below).

**Selection edges are not smoothed.** Like any typical audio editor, an effect on a selection is applied exactly as defined, with no automatic ramps at the edges. Gain, invert or reverse on a selection can leave a step at an edge unless the edges sit on zero crossings. Selection edges snap to zero crossings when snap is on (§4.6), which avoids most of these steps. *My call.* The "no new clicks" anti-goal is about Limewave's own playback mechanics (buffer swaps, envelope, cursors), not about audio the user deliberately edits.

Each effect is applied immediately: the waveform, seam view and audition update at once. Each application is one undo step. Effects that need a value open a small dialog that remembers the last values used.

| Effect | What it does | Parameters |
|---|---|---|
| Gain | Multiplies the range by a fixed gain. | dB, −48 to +48 |
| Normalize | Scales the range so its loudest sample peak (across all channels together) reaches the target. | target peak, dBFS, default −0.1 |
| Fade in | Rises from silence to full level across the range. | curve: linear, exponential, S-curve |
| Fade out | Falls from full level to silence across the range. | curve: linear, exponential, S-curve |
| Invert polarity | Flips the sign of every sample in the range. | none |
| Remove DC offset | Subtracts each channel's mean value over the range. | none |
| Reverse | Reverses the audio in the range. | none |

- **Reverse with no selection** reverses Start…End and **mirrors the markers with it**, so they stay on the same sounds: a frame `f` inside Start…End moves to `start + end − f`, so the loop start and loop end swap roles (new loop start = `start + end − old loop end`, new loop end = `start + end − old loop start`). Start and End stay where they are. Additional `smpl` loops are mirrored the same way. **Reverse of a selection** leaves all markers where they are.
- **Channel tools** (whole file only, enabled only where they make sense):
  - Stereo to mono: the average of left and right.
  - Swap left and right.
  - Mono to stereo: the mono channel copied to both.
  - On save, `fmt ` is rewritten for the new channel count (channels, block align, byte rate, and the channel mask for `WAVE_FORMAT_EXTENSIBLE` files). Sample format, bit depth and rate stay as in v0.1.
- **Auto-trim silence** (whole file): moves Start forward to the first frame and End back to the last frame where any channel's level is above a threshold (default −60 dBFS, adjustable in its dialog). It never moves Start past the loop start or End before the loop end. One undo step. It is a marker move, not an audio change.
- **Clipping:** effects work in floating point, so gain or normalize above 0 dBFS doesn't clip in the editor. When the result exceeds full scale, the effect dialog and the inspector show a "will clip when saved" warning; saving to integer formats clips, as in v0.1.
- **Order with the crossfade:** effects come first, then the crossfade is rendered on the processed audio, then the trim. The seam view shows that result.
- **Performance:** applying or undoing an effect on a 60-second 48 kHz stereo file should take well under half a second on a typical laptop, even with a few dozen effects in the list. *How (caching, checkpoints) is the builder's choice.*
- The effects live in an **Effects** menu in the toolbar; the selection actions (§4.6) and trims (§4.9) live in an **Edit** menu. *Exact placement and shortcuts are the builder's choice.*

### 4.8 Keeping metadata on save

This replaces the cue/adtl rule in v0.1 §6.6, and the v0.1 inspector warning "markers will be removed on save" goes away.

- **Shown and edited:** `smpl` only (plus the `ISFT` tag Limewave writes, and the `inst`/`acid` root and tune kept in step as in v0.1 §6.1).
- **Kept:** every other chunk, in its original order, including `cue `, `LIST/adtl` (labels, notes, labelled text), `LIST/INFO` fields other than `ISFT`, `inst`, `acid`, `fact` and chunks Limewave doesn't recognise.
- **A save with no edits** writes back the original file byte for byte except for `ISFT` (the v0.1 round-trip rule, now without the cue exception). This includes `smpl`: when loops, tuning and trim are unchanged, the original `smpl` bytes are kept as they are, rather than rebuilt. v0.1 rebuilds them, which resets loop 0's cue ID and recomputes the sample period. Likewise, audio outside every effect's range is written back with its original sample values, not re-encoded.
- **Positions follow the audio.** Cue points store sample positions. So that they keep pointing at the same audio:
  - a head trim (Start > 0) shifts every cue position by `−start`;
  - a whole-sample reverse (§4.7) mirrors cue positions inside Start…End the same way as the markers; a labelled-text range (`ltxt` with a sample length) is mirrored as a range, so its new start is the mirrored position of its old end;
  - cue points that fall outside the saved Start…End range are removed, together with their `adtl` entries (`labl`, `note`, `ltxt` with that cue ID); a labelled-text range that crosses Start or End is clipped to the saved range;
  - nothing else in those chunks changes.
- **A "Loop Range" cue** (some editors store the loop as a cue range as well as in `smpl`) is treated like any other cue: it follows trims and reverses but does **not** follow loop edits, so after moving the loop it can disagree with `smpl`. *My call: samplers read `smpl`, which Limewave keeps correct; keeping another program's marker in sync would mean editing cue markers, which is out of scope.*
- **Frame counts follow the audio.** A `fact` chunk's sample count is rewritten to the saved frame count. (v0.1 copies `fact` unchanged, which leaves a trimmed float WAV reporting the wrong length; this fixes it.) No other kept chunk is reinterpreted.
- If a kept chunk can't be parsed well enough to shift its positions (for example a malformed `cue ` chunk), it is copied unchanged and the inspector says so, rather than dropping it.

### 4.9 Trims based on loop points

Two Edit-menu actions, each one undo step and each just a marker move (the saved file is trimmed through the existing v0.1 trim):

- **Trim after loop end:** End = loop end + padding.
- **Crop to loop:** Start = loop start, End = loop end + padding. The saved file then begins exactly at the loop start. The crossfade still works, because it is rendered before the trim (v0.1 §6.6).

**Padding** is a number of frames kept after the loop end so a sampler's interpolation has data to read past it. Default 16, clamped to the file length, settable to 0 for files that must end exactly on the loop end. It is the same setting as the save dialog's existing "Trim after loop end, keep N" option, which stays for trimming many files at save time. Both actions are disabled when the loop is off.

## 5. Testing

As in v0.1 §8: unit tests in `limewave-core` with generated audio, UI tests with the existing test harness where they fit, and a manual checklist for what needs ears and eyes. New coverage:

- **Metadata kept:** no-edit round trip is byte-identical except `ISFT`, for files with `cue `, `adtl`, `fact` and unknown chunks; head trim shifts cue positions; cues outside the trim are removed with their `adtl` entries; reverse mirrors cue positions and `ltxt` ranges; `fact` sample count matches the saved frames; a malformed `cue ` is kept unchanged.
- **Backward loop:** type 2 read as Backward and written as type 2; playback order around the seam (forward to loop end, then backward, wrapping from loop start to loop end); crossfade not rendered while Backward and restored after switching back; mirrored snap gives a click-free seam on an exact-period sine.
- **Effects:** each effect on a selection and on Start…End; reverse-whole mirrors loop and extra `smpl` loops; effects then crossfade then trim, in that order; undo restores the audio exactly; channel tools rewrite `fmt ` correctly (including extensible files) and round-trip; normalize hits the target peak; auto-trim silence respects the loop.
- **ADSR:** level at each stage, release from mid-attack without a jump, release reaches silence in the set time, Stop releases instead of cutting, one-shots still end at the sample end.
- **Selection and trims:** set loop to selection (including moving Start/End outward), set Start/End to selection refuses to strand the loop, trim after loop end and crop to loop with padding 0 and 16.
- **UI:** dragging a marker by its label is one undo step; double-click label number entry; right-click on a key sets the root and is one undo step; click sets the play-from point and drag makes a selection; cursor positions published by the engine reach the UI (engine-level test; the visuals are checked by hand).
- **Manual checklist** additions: cursors move smoothly and in the right direction for forward, ping-pong and backward loops; ADSR sounds right and stopping never clicks; effects sound right; a file with cue markers from another editor still shows them in that editor after saving from Limewave.

## 6. Roadmap after v0.2 (new order)

Decided on 2026-10-20. This replaces the order in v0.1 §9; the content of each milestone is as described there unless noted.

1. **Tail rendering** (was M5). Comes straight after v0.2. Because it now arrives before the classifier and the loop finder, it works from the hand-set loop and the user's own choice of which files need a tail, rather than from automatic detection. Its design pass starts from the planning brief (`docs/LOOP_EDIT_HANDOFF.md`, local).
2. **SFZ instruments** (was M1). Picks up the v0.2 envelope as per-region `ampeg_*` values and gives right-click-drag on the keyboard its key-range meaning.
3. **Pitch detection**, **classifier**, **auto loop finder** (were M2–M4), in that order unless decided otherwise at the time.
4. **Beat slicing:** cutting rhythmic loops into hits at detected onsets, with rendered tails for each slice. After tail rendering, since it depends on it.

Someday: a sampler plugin version that honours backward loops (many samplers ignore them). The v0.1 rule of keeping the core library free of UI and audio-device code keeps this possible.

## 7. Calls I made (please check)

- One ADSR envelope for the session, remembered between runs, not saved into WAVs; defaults attack 2 ms, decay 0, sustain 100 %, release 30 ms.
- Crossfade is disabled for backward loops in v0.2.
- With no selection: gain, normalize, invert and DC removal process the entire file (normalize and DC removal measure Start…End), while fades and reverse work on Start…End.
- Effects on a selection get no automatic edge smoothing, as in a typical audio editor.
- Play selection releases at the selection end and lets the release ring into the following audio.
- A no-edit save keeps the original `smpl` bytes and the untouched audio exactly.
- Reverse with no selection mirrors the markers; reverse of a selection leaves them alone.
- Set Start/End to selection is included alongside Set loop to selection.
- Set loop to selection turns the loop on (Forward) if it was off, and moves Start/End outward when needed.
- Selection edges snap to zero crossings when snap is on.
- Keyboard and MIDI notes always start at Start; only the Play button uses the play-from point.
- A "Loop Range" cue follows trims and reverses but not loop edits.
- The `fact` chunk's sample count is now kept correct (a v0.1 gap).
- The save dialog's "Trim after loop end" option stays, sharing its padding with the new Edit-menu trims.
- Right-click-drag on the keyboard is reserved for SFZ key ranges and does nothing in v0.2.
- The version becomes 0.2.0 (so `ISFT` reads `Limewave 0.2.0`).

## 8. Left to the builder

- How processed audio is cached so effects and undo stay fast.
- The mirrored zero-crossing rule for backward loops, within §4.3's requirement.
- Menu placement, shortcuts, dialog layout, the play-from marker's look, and whether the envelope section draws the envelope shape.
- Exact fade curve formulas for the exponential and S-curve fades.
